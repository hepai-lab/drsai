## 1. 评测维度总览

智能体评测目前已从单一的"准确率"指标发展为多维评测体系，主要涵盖以下能力维度：

| 能力维度 | 核心考察点 | 代表性 Benchmark |
|---------|-----------|-----------------|
| **代码能力** | 代码生成、Bug 修复、仓库级理解、软件工程全流程 | SWE-bench, LiveCodeBench, HumanEval |
| **深度检索与资料整合** | 多跳搜索、信息综合、长程推理、事实准确性 | GAIA, BrowseComp, SimpleQA, HLE |
| **文档/电脑操作** | GUI 理解、跨应用工作流、操作系统级任务执行 | OSWorld, WebArena, AndroidWorld |
| **工具使用** | 函数调用、多轮工具交互、API 编排、策略遵循 | τ-bench, ToolBench, BFCL, API-Bank |
| **综合智能** | 多维度能力整合、人机对齐 | Agent-as-a-Judge, Chatbot Arena |

**评测方法论趋势：**
- 从单次运行准确率 → **可靠性指标 pass^k**（多次运行一致性）
- 从人工评估 → **AI-as-a-Judge**（规模化自动评估）
- 从模拟环境 → **真实环境**（真实 OS、真实 Web、真实 GitHub repos）
- 从纯准确率 → **准确率 + 成本 + 延迟**多维评估

## 2. 代码能力评测

### 2.1 SWE-bench / SWE-bench Verified

**名称：** SWE-bench: Can Language Models Resolve Real-World GitHub Issues?

**论文：** https://arxiv.org/abs/2310.06770

**GitHub：** https://github.com/swe-bench/SWE-bench

**排行榜：** https://www.swebench.com/

**评测方案：**
- 从 12 个流行 Python 开源仓库（Django, Flask, scikit-learn, sympy 等）的真实 GitHub Issue 中收集任务
- 每个任务给定一个 issue 描述和对应的代码仓库快照
- 智能体需要自主导航代码库、定位问题文件、编写修复补丁
- **评估方式：** 执行自动化测试用例（FAIL_TO_PASS 和 PASS_TO_PASS 测试），判断补丁是否正确解决问题
- **完全自动化评估**，无需人工判断

**SWE-bench Verified（验证集）：**
- 由 OpenAI 协助筛选的 500 个高质量、可解的子集
- 使用统一的 mini-SWE-agent harness 评估所有模型，确保公平
- 论文/介绍：https://openai.com/index/introducing-swe-bench-verified/

**SWE-bench 全量集：** 2,294 个任务

**当前 SOTA 分数（SWE-bench Verified，2026-02 排行榜实时数据）：**

| 排名 | 模型 | 解决率 (%) | 成本 ($) | Agent | 日期 |

| 1 | Claude 4.5 Opus (high reasoning) | 76.80% | $0.75 | mini-SWE-agent v2 | 2026-02 |
| 2 | Gemini 3 Flash (high reasoning) | 75.80% | $0.36 | mini-SWE-agent v2 | 2026-02 |
| 3 | MiniMax M2.5 (high reasoning) | 75.80% | $0.07 | mini-SWE-agent v2 | 2026-02 |
| 4 | Claude Opus 4.6 | 75.60% | $0.55 | mini-SWE-agent v2 | 2026-02 |
| 5 | GPT-5-2 Codex | 72.80% | $0.45 | mini-SWE-agent v2 | 2026-02 |

**历史分数演进：**
- 2024-03: Devin (Cognition) 首次报告 13.86%（当时的 SOTA）
- 2024-10: Claude 3.5 Sonnet + SWE-agent ~30%+
- 2025-05: Claude 3.7 Sonnet + SWE-agent ~50-60%
- 2026-02: Claude 4.5 Opus 76.80%（当前 SOTA）

**关键特点：**
- 真实世界软件工程问题，非合成数据
- 基于测试的完全自动化评估
- 统一 harness (mini-SWE-agent) 确保公平比较
- 同时报告成本（$）和解决率

### 2.3 LiveCodeBench

**名称：** LiveCodeBench: Holistic and Contamination Free Evaluation of Large Language Models for Code

**论文：** https://arxiv.org/abs/2403.07974

**GitHub：** https://github.com/LiveCodeBench/LiveCodeBench

**评测方案：**
- ** contamination-free（无污染）**评测：不断更新题库，避免模型训练时见过题目
- 涵盖代码生成、代码执行、测试用例生成、代码修复等多维度
- 题目来源于 LeetCode、AtCoder 等竞赛平台的新题
- 按时间窗口评测，确保模型未在训练数据中见过
- 自动化测试评估

**关键特点：**
- 解决了 HumanEval 等经典 benchmark 的数据污染问题
- 持续更新的活评测（live benchmark）
- 包含 8 个维度的代码能力评测

### 2.4 HumanEval / MBPP

**HumanEval:**
- OpenAI 2021 年发布，164 个 Python 编程题
- 论文：https://arxiv.org/abs/2107.03374 (Codex 论文)
- 评估方式：pass@k（生成 k 个解中至少一个通过测试的概率）
- GitHub：https://github.com/openai/human-eval
- 当前 SOTA：~95%+ pass@1（多数前沿模型）

**MBPP (Mostly Basic Python Problems):**
- Google 发布，974 个基础 Python 编程题
- 评估方式：pass@1
- GitHub：https://github.com/google-research-datasets/mbpp
- 当前 SOTA：~90%+ pass@1

**局限性：** 两个 benchmark 均存在严重数据污染问题，许多模型在训练时已见过题目。

**论文：** https://arxiv.org/abs/2406.15877

**GitHub：** https://github.com/bigcode-project/bigcode-bench

**排行榜：** https://bigcode-bench.github.io/

**评测方案：**

- 要求模型调用标准库和第三方库 API

## 3. 深度检索与资料整合评测

### 3.1 GAIA (General AI Assistants)

**名称：** GAIA: a benchmark for General AI Assistants

**论文：** https://arxiv.org/abs/2311.12983

**GitHub / HuggingFace：** https://huggingface.co/spaces/gaia-bench/leaderboard

**评测方案：**
- 由 Meta/Facebook AI 发布的真实世界问答 benchmark
- 466 个问题，分 3 个难度级别：
  - **Level 1：** 简单任务，通常 1-3 步即可解决
  - **Level 2：** 中等任务，需要多步推理和工具使用
  - **Level 3：** 复杂任务，需要长程推理、多工具组合、多模态理解
- 任务类型包括：网络搜索、文件处理、数据分析、图表理解、多模态推理
- 智能体可使用网络浏览器、代码执行器、文件操作等工具
- **评估方式：** 精确匹配最终答案（exact match），完全自动化

**分数（历史演进）：**
| 系统/模型 | GAIA Overall | GAIA L1 | 日期 |
|-----------|-------------|---------|------|
| 人类基线 | 92% | ~92% | 2023-11 |
| GPT-4 (无工具) | ~15% | ~30% | 2023-11 |
| GPT-4o + 工具 | ~30-40% | ~50% | 2024-05 |
| Magentic-One (GPT-4o) | ~27-30% | — | 2024-11 |
| OpenAI Deep Research | **67.36%** | ~73% | 2025-02 |
| Manus | — | **~86.5%** | 2025-03 |
| Gemini 2.5 Pro | ~65-70% | — | 2025-03 |

**关键特点：**
- 被公认为通用智能体评测的"黄金标准"
- 考察多步推理、工具使用、多模态理解的综合能力
- 真实世界问题，非合成数据
- 完全自动化的答案匹配评估

### 3.2 BrowseComp

**名称：** BrowseComp: A Simple-but-Challenging Benchmark for Web Browsing Agents

**发布方：** OpenAI

**网址：** https://openai.com/index/browsecomp/ (博客)
**论文：** https://arxiv.org/abs/2504.13716 (待确认)

**评测方案：**
- 1266 个需要深度网络搜索才能回答的困难问题
- 每个问题都需要多跳搜索（multi-hop search）和信息整合
- 问题设计为：简单关键词搜索无法直接找到答案
- 需要智能体浏览多个网页、提取并综合信息
- **评估方式：** 精确匹配答案，完全自动化

**MM-BrowseComp（多模态版本）：**
- 论文：https://arxiv.org/abs/2508.13186
- 多模态网页浏览评测的扩展

**关键特点：**
- 专注于深度检索能力，而非简单的单次搜索
- 问题难度高，需要复杂推理路径

### 3.3 SimpleQA

**名称：** SimpleQA: Measuring Short-Form Factuality in Large Language Models

**发布方：** OpenAI

**论文：** https://openai.com/index/simpleqa/ (博客)

**评测方案：**
- 短形式事实问答 benchmark
- 4326 个需要事实知识的问题
- 每个问题有明确的、可验证的答案
- 评估方式：精确匹配答案
- 三个评分等级：正确 / 不正确 / 没有回答

**关键特点：**
- 专注于事实准确性，而非推理深度
- 简单但有效的评测模型基础知识的能力
- 是评估模型幻觉问题的重要工具

### 3.4 FanOutQA

**名称：** FanOutQA: A Multi-Hop, Multi-Document Question Answering Benchmark for Large Language Models

**论文：** https://arxiv.org/abs/2402.14116

**GitHub：** https://github.com/FanOutQA/FanOutQA

**评测方案：**
- 多跳、多文档问答 benchmark
- 每个问题需要从多个来源收集信息并综合回答
- 考察"扇出"（fan-out）式信息检索能力
- 评估方式：自动化答案匹配 + 人工评估

### 3.5 HLE (Humanity's Last Exam)

**名称：** Humanity's Last Exam

**发布方：** Center for AI Safety / Scale AI

**网址：** https://lastexam.ai/

**论文：** https://arxiv.org/abs/2501.02256 (待确认)

**评测方案：**
- 跨学科的高难度问答 benchmark

- 3000+ 道题目

### 3.6 Mind2Web 2

**名称：** Mind2Web 2: A Benchmark for Agentic Search

**论文：** https://arxiv.org/abs/2506.21506

**评测方案：**
- 130 个长程智能体搜索任务
- 每个任务需要智能体在网页上进行多步搜索并综合信息
- 使用树结构评分标准（tree-structured rubric）进行评估
- 支持部分分数（partial credit），而非简单的全对/全错
- 评估方式：AI judge + 人工标注的评分标准

## 4. 文档/电脑操作评测

### 4.1 OSWorld

**名称：** OSWorld: Benchmarking Multimodal Agents for Open-Ended Tasks in Real Computer Environments

**论文：** https://arxiv.org/abs/2404.07972

**GitHub：** https://github.com/xlang-ai/OSWorld

**网站：** https://os-world.github.io/

**评测方案：**
- 首个真实计算机环境的多模态智能体 benchmark
- 支持 Ubuntu、Windows、macOS 三种操作系统
- 369 个真实世界电脑任务，涉及：
  - 桌面应用操作（Chrome, VS Code, LibreOffice, GIMP 等）
  - 文件 I/O 操作
  - 跨应用工作流（如从网页提取数据写入表格）
  - OS 系统设置
- 每个任务包含：详细的初始状态配置 + 基于执行的评估脚本
- **评估方式：** 执行式评估——运行自定义验证脚本检查最终系统状态，完全自动化
- 支持交互式学习

**分数：**
| 系统 | 成功率 | 对比 |
|------|--------|------|
| 人类基线 | 72.36% | — |
| 最佳模型 (2024-04 初始) | 12.24% | — |
| OpenAI Operator (2025-01) | 38.1% | — |

**OSWorld-Human 扩展（2025-06）：**
- 论文：https://arxiv.org/abs/2506.16042
- 包含人工标注的人类执行轨迹
- 增加了时间效率评测维度
- 发现最佳智能体也需要比人类多 2.7-4.3 倍的步骤

**关键特点：**
- 真实 OS 环境，而非模拟器
- 开放式任务，涉及任意应用
- 完全自动化、可复现的评估
- 人类基线提供清晰的性能差距参照

## 5. 工具使用评测

### 5.1 τ-bench (tau-bench)

**名称：** τ-bench: A Benchmark for Tool-Agent-User Interaction in Real-World Domains

**论文：** https://arxiv.org/abs/2406.12045

**GitHub：** https://github.com/sierra-research/tau-bench (已升级为 τ³-bench)
**τ³-bench：** https://github.com/sierra-research/tau3-bench

**评测方案：**
- 模拟真实世界中的"工具-智能体-用户"三方交互
- 智能体拥有领域特定的 API 工具和策略指南
- 用户由 LLM 模拟（模拟真实用户的行为和对话）
- 三个领域：
  - **Retail（零售）：** 电商客服场景，处理订单管理、退货、支付等
  - **Airline（航空）：** 航空客服场景，处理航班预订、改签、行李等
  - **Banking（银行）：** τ³-bench 新增，银行业务场景
- **核心创新：pass^k 可靠性指标** —— 同一任务运行 k 次，只有 k 次全部通过才算 pass^k
  - pass^1 = 单次准确率
  - pass^k = k 次运行全部成功的概率（衡量可靠性/一致性）
- **评估方式：** 基于数据库最终状态的自动化验证

**排行榜分数（tau-bench v1）：**

| 策略/模型 | Retail pass^1 | Retail pass^2 | Airline pass^1 | Airline pass^2 |
|-----------|--------------|--------------|----------------|----------------|
| TC (Claude 3.5 Sonnet 20241022) | 0.692 | 0.576 | 0.460 | 0.326 |
| TC (GPT-4o) | 0.604 | 0.491 | 0.420 | 0.273 |
| TC (Claude 3.5 Sonnet 20240620) | 0.626 | 0.506 | 0.360 | 0.224 |
| TC (GPT-4o-mini) | — | — | 0.225 | 0.140 |
| Act (GPT-4o) | — | — | 0.365 | 0.217 |
| ReAct (GPT-4o) | — | — | 0.325 | 0.233 |

*TC = Tool-Calling 策略*

**关键特点：**
- **pass^k 指标是重要创新**：解决了传统 benchmark 只测单次准确率的问题
- 真实的多轮对话交互（用户会追问、改主意）
- 策略遵循评测（智能体必须在规定策略内操作）
- 完全自动化的状态验证

## 8. 评测方法论趋势与挑战

### 8.1 评测方法论演进趋势

| 趋势 | 从 → 到 | 代表性创新 |
|------|---------|-----------|
| **评估维度** | 单一准确率 → 多维评估 | pass^k 可靠性、成本-准确率权衡 |
| **评估环境** | 模拟环境 → 真实环境 | OSWorld (真实 OS)、SWE-bench (真实 repos) |
| **评估方式** | 人工评估 → AI-as-a-Judge | Agent-as-a-Judge (85.4% 人类一致率) |
| **运行方式** | 单次运行 → 多次运行 | τ-bench pass^k 指标 |
| **评测数据** | 固定数据集 → 持续更新 | LiveCodeBench (contamination-free) |
| **评估范围** | 单维度 → 综合评测 | GAIA (多步推理+工具+多模态) |

### 8.2 关键挑战

参考 "AI Agents That Matter" (Princeton, https://arxiv.org/abs/2407.01502)：

1. **成本盲区 (Cost Blindness)：** 大多数 benchmark 不报告推理成本
   - 解决方案：SWE-bench Verified 现在报告每任务成本（$）
   
2. **可靠性缺失 (Reliability Gap)：** 单次准确率掩盖了不一致性
   - 解决方案：τ-bench 的 pass^k 指标
   
3. **过拟合 (Overfitting)：** 智能体可能过拟合到特定 benchmark 版本
   - 解决方案：LiveCodeBench 的持续更新策略

4. **可复现性 (Reproducibility)：** 许多 SOTA 声称无法独立复现
   - 解决方案：统一 harness（如 mini-SWE-agent）和公开排行榜

5. **数据污染 (Contamination)：** Benchmark 数据可能泄漏到训练数据中
   - 解决方案：contamination-free 设计、按时间窗口评测

6. **商业产品评测困难：** Devin、Cursor、Manus 等商业产品报告选择性分数，独立验证不足
   - 解决方案：社区驱动的评测（如 Chatbot Arena 扩展到智能体）

### 8.3 评测方案建议

对于一个全面的智能体评测方案，建议采用以下组合：

| 能力维度 | 首选 Benchmark | 备选 Benchmark |
|---------|---------------|---------------|
| 代码能力 | SWE-bench Verified | LiveCodeBench, BigCodeBench |
| 深度检索 | GAIA | BrowseComp, SimpleQA, HLE |
| 电脑操作 | OSWorld | WebArena, AndroidWorld |
| 工具使用 | τ-bench (pass^k) | BFCL, ToolBench, API-Bank |
| 综合评测 | Agent-as-a-Judge | AgentBench, AgentBoard |
| 人类偏好 | Chatbot Arena/AgentArena | — |
