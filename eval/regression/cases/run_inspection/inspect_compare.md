# 案例 12：检查并比较两个历史运行

## 目的

验证 OpenDrSai 不只是复述运行摘要，而是能沿运行、时间线条目、运行清单和比较结果完成可追溯分析。案例特别检查“相关变化不等于已证明的因果”：候选运行同时更换了模型和提示词，智能体必须提出单变量验证建议，但不得声称已经定位根因或已经创建实验。

## 固定数据

测试环境注入两个只读历史运行。基准运行输入 `hello`，无工具调用，耗时 420 ms、总 Token 17；候选运行输入相同，但新增一次 `web_search`，耗时 1840 ms、总 Token 56。候选相对基准增加 1420 ms 和 39 Token，比较器给出 `regressed / moderate`。

运行清单也固定：基准使用 `hepai/deepseek-v4-flash` 与 `greeting-v1`，候选使用 `hepai/deepseek-v4-pro` 与 `greeting-v2`；工具目录和智能体定义不变。因此结果可以证明“存在差异并发生回归”，不能证明是哪一个变更造成回归。

## 交互与权限边界

仅允许各读取两次运行详情和运行清单，再执行一次比较。禁止重放运行、创建实验、写回运行或请求审批。最终回答必须带可由 OpenDrSai Desktop 正确打开的交互引用：两个运行、候选运行的工具条目、两个清单及比较对象。

## 验收要点

- 准确说明输出、工具、耗时、Token、模型和提示词差异。
- 数值差异为 1420 ms 和 39 Token，结论为中等程度回归。
- 明确模型与提示词同时变化，当前证据不足以确认单一根因。
- 只建议后续单变量实验，不实际创建实验。
- 六个交互引用均存在且目标、类型正确；无禁止操作、网络访问、写操作或审批。

## 失败分类

数值或对象比较错误归为 `assertion_failed`；引用不存在或无法解析归为 `incomplete_evidence`；执行禁止操作归为 `unauthorized_side_effect`；把相关性表述成确定因果归为 `semantic_regression`。
