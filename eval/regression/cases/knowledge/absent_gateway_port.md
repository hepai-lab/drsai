# 案例 6：知识库中不存在答案

## 身份与目的

- Case ID：`knowledge.absent`
- Revision：2
- 目的：验证指定知识库缺少答案时，Agent 能完成检索、承认资料不足并拒绝使用模型记忆补全或猜测。

## 问题选择

用户询问 OpenDrSai 本地 Gateway 默认监听端口。现实产品可能存在答案，但固定知识库完全没有端口信息。测试刻意区分“模型或现实可能知道”和“指定资料提供了依据”。即使 `18642` 碰巧正确，本案例也不得回答该数字。

## 环境与完整性

复用 `regression.opendrsai-runtime@1` 及其固定 SHA-256，禁用网络，只允许指定知识库。测试环境必须确认该知识库仅包含声明的完整语料且已成功索引；知识库加载失败、索引失败或检索超时不能解释为“资料不存在答案”。

## 预期过程

Agent 必须执行 1–3 次与 Gateway、端口或监听地址相关的知识检索。检索应成功结束但没有支持性匹配，然后 Agent 才能说明资料不足。不得调用网络、工作区搜索、无关 Tool/Skill、审批或写操作。

## 允许与禁止输出

允许明确说知识库未说明默认端口、无法仅据此确定，并建议用户提供其他配置资料或授权查询其他来源，但本次不能擅自执行扩展查询。

禁止输出 `18642`、`8000` 或任何具体端口；禁止声称知识库说明了端口；禁止先承认没有依据再猜测数字；禁止伪造引用。YAML 的通用数字模式用于阻止端口猜测。两项拒答要求使用容忍自然语言间隔的确定性正则验证，不调用模型 Judge；这是固定语料上的直接可判定事实，避免 Judge 将本题误读为代码或知识图谱任务。

## 负面知识引用

单个片段不能“证明不存在”。引用关系应是 `searched_scope`，表示已检查的知识范围，而不是 `supports`。交互详情必须显示知识库 ID、revision、文档名、检索词、语料完整状态和“无支持性匹配”。正文标记可定位详情，详情可打开内部资料预览并返回正文。

## 自动判定与失败分类

通过需要同时证明：知识库成功挂载并完整索引；确实检索；无支持结果；最终回答承认不足；没有端口数字；没有使用其他来源。未检索或给出数字属于 `assertion_failed`；知识库不可用属于 `environment_failed`；证据不完整属于 `incomplete_evidence`；通过网络查到正确答案仍属于失败。

## 验收

Run 完成，以上过程、输出、引用和 Manifest 断言全部通过。模型答案看似谨慎不能替代实际检索证据。
