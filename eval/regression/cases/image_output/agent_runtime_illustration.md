# 案例 9：生成指定主题和比例的图片

## 身份与目的

- Case ID：`image.output.simple`
- Revision：1
- 目的：验证 OpenDrSai 选择正式图片生成能力，生成满足格式、比例、构图和禁止元素要求的真实 PNG，并以可交互 Artifact 交付。

## 基准策略

本案例不保存参考图片。Codex 内置图片生成服务在准备基准时因执行环境 IP 未获授权返回 401，用户决定不使用 CLI/API 回退，也不生成图片基准。因此采用 `specification_only`：以结构、语义、视觉阈值和 Artifact 证据判定，不进行像素比较。

未来即使生成参考图，也只能用于校准人工或视觉 Evaluator，不能把像素相似度设为发布门禁。新增参考图需要提升 Case revision 并记录来源和摘要。

## 任务设计

用户要求 16:9 横版、深蓝背景、中央发光核心、与五类外围能力相连，蓝色/青色强调，简洁现代且无人物、文字、Logo 或水印。五类能力分别为消息、工具、知识、图片和安全，可使用对话气泡、齿轮/工具、书本/文档、图片框和盾牌/锁等无文字符号表达。

核心可以是球体、晶体、抽象芯片或能量节点；节点位置、连线形态、蓝色深浅和少量紫白辅助色允许变化。五个完全相同且无语义的圆点不能满足“五类能力”。

## 环境与过程

网络标记为 `required`，因为本案例要验证当前 Agent 配置所绑定的正式图片生成提供方，而不是离线 Fixture；开始前必须由预检和范围确认明确披露外部调用。知识库和 Presentation Skill 禁用，只启用正式图片生成能力。允许生成 1–2 次，以便修正比例或明显内容问题，但不得无限重试刷结果。每次生成保留独立证据，最终只交付一个 PNG Artifact。

图片后端不可用属于 `environment_failed`；不能用 SVG、Mermaid、ASCII、文字描述或临时 URL冒充图片生成结果。

## 文件验收

最终文件为隔离 Workspace 下 `artifacts/opendrsai-agent-runtime.png`，至少 1280×720，长宽比相对 16:9 的误差不超过 2%，颜色模式为 RGB 或 RGBA，文件可解码，大小不少于 20 KB，并记录 MIME、尺寸和 SHA-256。

## 视觉验收

视觉 Evaluator 检查深蓝主背景、中央发光核心、可见连接、五类不同能力、蓝青强调和简洁现代风格。OCR 检查高置信度文字、字母和数字；低于 0.75 的识别不直接阻断，以降低装饰线条误报。人物、人脸、Logo、水印或大面积暖色背景均失败；临界 OCR 和视觉分歧进入人工复核。

## Artifact 交互

最终回答必须显示可交互图片 Artifact，可在 OpenDrSai 中预览和打开原图。Artifact 的 ID、MIME、尺寸、摘要和路径必须与 Run Inspector 一致，并关联到本次图片生成调用。失效临时 URL 或纯文本路径不算交付。

## 通过标准

Run 完成；调用图片生成 1–2 次；最终只有一个合规 PNG；格式、尺寸和比例通过；视觉必需项满足且禁止项不存在；没有无关能力或越界写入；Artifact、生成调用和 Run 关系完整。由于没有图片文件基准，视觉 Evaluator 配置与版本必须随结果保存，避免历史评分语义漂移。
