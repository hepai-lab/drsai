# OpenDrSai Codex 用户体验 V5 开发方案

状态：已完成  
目标：让普通用户能够确认 Codex 是否可用、会话是否完整、当前消息是否延续原任务，并能在故障时自行恢复或导出脱敏诊断；所有跨 Backend 的会话展示仍只依赖 OAEP。

## 1. 设计原则

1. 用户界面使用“任务、会话、同步、连接”等产品语言，不暴露 OAEP、mapping version、projection correction 等内部术语。
2. 关键操作必须有可见入口、进行状态、成功反馈和失败恢复。
3. 历史与实时消息使用同一 OAEP Projector，不能为 Codex 编写私有渲染分支。
4. Desktop、Runtime、Codex Backend 通过显式身份与能力握手建立可信连接，不能只检查端口。
5. 多轮输入默认延续当前 Codex Thread；无法延续时必须告知用户，不能静默创建新 Thread。
6. 所有重试和重连保持幂等，不生成重复 Run、Item 或消息。
7. 诊断数据默认脱敏，不包含令牌、Cookie、凭据、消息正文或宿主机绝对路径。

## 2. 模块与功能点

### M1 会话可信度（5 项）

1. 展示同步状态：未同步、同步中、已同步、部分完成、失败。
2. 展示最近同步时间和已加载 Run 数量。
3. 首次打开立即进入历史加载状态，不保留初始空白输入页。
4. Adapter 重新投影完成后显示用户语言的格式更新提示。
5. 检测缺失/重复 sequence、重复 Backend Run 和投影异常，并安全降级。

### M2 Runtime 与 Codex 状态（6 项）

1. Runtime 身份返回 runtime、instance、版本、协议和运行模式。
2. Codex 状态返回安装、版本、登录、App Server、传输和 Adapter 信息。
3. Desktop 启动验证 Runtime 身份与协议能力，不复用不匹配实例。
4. 设置页提供 Codex 状态总览。
5. 提供一键检测、重新连接和可恢复故障的一键修复。
6. 断线后保留输入、恢复 Event cursor，并阻止重复消息。

### M3 会话操作与归档（6 项）

1. 工作区提供新建会话、搜索、同步、归档入口。
2. 支持查看、搜索、归档和取消归档。
3. Codex 归档状态双向同步。
4. 保存归档来源、更新时间和冲突诊断信息。
5. 会话显示来源：OpenDrSai、本机 Codex、远程 Codex。
6. 核心操作不只放在省略号菜单。

### M4 历史加载与导航（6 项）

1. 按 Run 分页，初次加载最近内容。
2. 向上滚动加载更早 Run，并保持视口位置。
3. 超大工具输出、Diff 和媒体按需展开。
4. 提供回到最新消息和未读定位。
5. 支持会话内搜索和按日期定位。
6. 加载失败提供重试，不退回初始输入页。

### M5 结构化内容体验（6 项）

1. 默认突出用户消息和最终回答。
2. reasoning、plan、command、tool、file、subtask 归入可折叠处理过程。
3. 文件修改显示文件数、增删行和 Diff/打开入口。
4. 命令显示状态、耗时和关键错误，完整输出按需查看。
5. artifact、interaction、notice 使用专用卡片。
6. 图片、音频、文件和远程资源提供可理解的可用/不可用状态。

### M6 多轮连续对话（6 项）

1. 已绑定会话默认复用原 Codex Thread。
2. 输入区显示“将在当前 Codex 任务中继续”。
3. 无法恢复原任务时阻止静默新建，并提供明确选择。
4. 每次发送使用稳定客户端请求 ID。
5. 网络重试复用请求 ID，Runtime 幂等创建 Run。
6. 运行中追加消息提供追加、排队、中断后发送的明确语义。

### M7 用户错误与诊断（5 项）

1. 内部错误码映射为用户可理解的说明和下一步操作。
2. 错误卡片提供重试、查看详情和复制诊断。
3. 设置页提供一键生成脱敏诊断报告。
4. 报告包含 Desktop、Runtime、Codex、OAEP、Adapter、连接和同步统计。
5. 未知 Codex Item 降级为通用活动，不阻断整个会话。

### M8 自动测试与验收（6 项）

1. Runtime/Codex 状态契约测试。
2. OAEP 顺序、异常降级和历史分页测试。
3. 归档双向同步和冲突测试。
4. 同 Thread 多轮、重试幂等和恢复测试。
5. Desktop 加载、错误、折叠、导航和诊断验证。
6. Windows 宿主机真实 Codex Thread 端到端验收。

总计：8 个模块，46 个功能点。

### P1：可管理、可理解、可恢复

- M3 全部。
- M5 全部。
- M7 全部。
- 对应自动测试。

### P2：大型会话产品化

- M4 全部。
- 真实大型 Codex Thread 的性能与恢复验收。

## 4. 完成门槛

1. 用户打开 Codex 会话后立即看到加载反馈，最终按正确轮次显示内容。
2. 用户能确认同步是否完成、最近同步时间及失败后的恢复操作。
3. 用户能在设置中确认 Codex 是否安装、登录和可连接。
4. 本地开发启动不会复用旧安装版 Gateway。
5. 已有 Codex 会话连续发送至少三轮仍使用同一 Thread。
6. 发送超时重试不会产生重复 Run 或重复用户消息。
7. 归档与取消归档能和 Codex 对齐。
8. 大型历史按 Run 加载，滚动位置稳定，超大内容不会阻塞页面。
9. UI 不显示内部对象字符串、绝对路径或未经解释的内部错误码。
10. 自动测试、Windows 类型检查、协议校验和真实 Codex E2E 全部通过。

## 5. 进度记录

- 第 1 轮：方案建立，开始审计已有能力与 V5 差距。
- 第 2 轮：完成同步可信状态、Runtime/Codex 分层状态和大型历史首屏窗口。
- 第 3 轮：完成会话导航、用户错误映射、绑定丢失保护和脱敏诊断。
- 第 4 轮：完成按轮次加载、结构化摘要、归档冲突策略和既有能力审计。
- 第 5 轮：建立并通过 46 项 V5 自动验收账本。
- 第 6 轮：真实 Codex 三轮连续对话、OAEP、归档、审批、取消及重启恢复通过。
