# 远程工作区人工体验指南

本指南使用独立 Docker Linux 容器体验当前 Desktop 的远程工作区，不依赖 `remote_3090`，也不影响正式的 1 小时稳定性验收证据。

## 1. 启动隔离环境

```powershell
cd C:\Users\win11\VSProjects\drsai\apps\desktop\windows
npm run demo:remote-workspace
```

脚本会构建真实 OpenDrSai Python Runtime，启动容器 `opendrsai-remote-workspace-demo`，并生成明确标记的临时 Ed25519 凭据。默认 SSH 端口为 `22331`。

## 2. 启动 Desktop

在同一个 PowerShell 窗口执行：

```powershell
$env:OPENDRSAI_SSH_CONFIG = "$PWD\.cache\remote-workspace-demo\ssh_config"
npm run dev
```

也可以在设置环境变量后启动已构建版本：

```powershell
& .\release\win-unpacked\OpenDrSai.exe
```

## 3. 界面验收

1. 登录并进入主界面，点击“添加工作区”。
2. 确认只显示“本地”和“远程”，选择“远程”。
3. 选择计算机 `opendrsai-demo`。
4. 首次连接时核对并信任本机 `127.0.0.1:22331` 的临时主机指纹。
5. 选择 `/home/vscode/workspace`，点击“打开远程工作区”。
6. 查看 `README.md`、`remote.txt` 和 Git 状态；在终端运行 `pwd`、`uname -a`，确认执行位置是 Linux 容器。
7. 新建 Session/Run，观察 Event、审批、文件变化和终端输出。
8. 再添加 `/home/vscode/workspace-two`，确认一个 Runtime 可管理多个相互隔离的 Workspace。

建议额外体验：修改 `remote.txt` 后查看 Git Diff；执行需要审批的写操作；在 Docker Desktop 中暂停并恢复容器，观察断线及恢复提示。

## 4. 清理

先关闭体验用 Desktop，再执行：

```powershell
npm run demo:remote-workspace:stop
```

该命令只删除体验容器和 `.cache\remote-workspace-demo` 中的临时密钥、`known_hosts` 与 SSH 配置。
