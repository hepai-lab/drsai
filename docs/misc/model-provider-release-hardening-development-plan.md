# 模型服务配置发布加固与体验完善开发方案

## 1. 文档目的

本文定义自定义 API Key、Base URL、模型与 Provider 配置功能在主体实现完成后的下一阶段工作。当前事务配置、凭据安全、Gateway、CLI、TUI、Desktop、诊断、恢复与 Windows 产物验证已经具备；本阶段不继续扩张配置字段，而是把现有能力收敛为可审查、可复现、可跨平台发布且不易误操作的产品能力。

本阶段聚焦五个结果：

1. 将混合工作区中的功能改动整理为边界清晰、可回退的交付单元；
2. 补齐 Desktop 真实用户操作 E2E，而不只验证 API、IPC 和静态契约；
3. 完成 macOS 签名产物、Keychain 和打包后 Gateway 的发布门禁；
4. 建立真实 Provider 兼容矩阵，验证模拟服务无法覆盖的协议差异；
5. 消除删除、恢复和连接测试中的用户认知歧义，并治理仓库剩余门禁失败。

## 2. 当前基线

### 2.1 已具备能力

- 完整候选配置预览、校验、原子提交、回滚和 `revision` 冲突检测；
- 进程内及跨进程写入保护、最后已知可用快照；
- Windows DPAPI、macOS Keychain 和加密文件凭据存储；
- 安全存储、环境变量、无 Key 三种互斥认证来源；
- HepAI、OpenAI、Anthropic、DeepSeek、Ollama 及自定义兼容服务预设；
- 无副作用草稿测试、模型发现、Doctor、状态、恢复和凭据清理；
- Gateway、CLI、TUI、Windows/macOS Desktop 接入；
- Windows 生产构建、解包产物、Electron IPC 和 Gateway HTTP 冒烟。

### 2.2 已知缺口

- 当前工作区混有 Android、OAEP、Relay 等其他开发改动，模型配置功能尚未形成独立、可复现的提交序列；
- macOS 尚未在真实签名产物中验证 Keychain、IPC、Gateway 和重启恢复；
- Desktop 自动化主要覆盖接口和产物契约，缺少真实点击与表单状态 E2E；
- 删除 Provider 使用二选一确认框表达三个语义，“取消”仍执行删除，存在误操作风险；
- Desktop 默认仅执行 `basic` 探测，用户不容易分辨“服务可连接”和“指定模型已实际调用”；
- 真实 Provider、代理、TLS 和仅聊天端点的兼容性尚未形成持续门禁；
- Python 全量基线仍记录 4 个非本功能失败，发布状态不能表述为全绿。

## 3. 范围与非目标

### 3.1 本阶段范围

- Git 交付边界和可复现门禁；
- Desktop 配置流程交互修正和 UI E2E；
- macOS 发布流水线及真实设备验收；
- 真实 Provider 兼容性测试；
- 现有失败基线治理、文档和发布检查表。

### 3.2 非目标

- 不新增新的 TOML 核心字段；
- 不重写现有事务配置服务；
- 不把 Provider 产品目录扩展为在线市场；
- 不在自动测试中长期保存真实用户 Key；
- 不顺带修复与本功能无关的大规模 Android、OAEP 或 Relay 需求；相关问题只做基线化或独立拆分。

## 5. 详细开发方案

### 5.1 工作包 A：交付边界与可复现构建

目标是让所有验收结果对应到确定的 commit，而不是对应到一个混合工作区。

实施内容：

1. 建立模型配置功能文件清单，区分新增、修改、生成物和文档；
2. 将无关 Android、OAEP、Relay 改动从本功能提交中排除，不覆盖或删除他人改动；
3. 按以下顺序整理提交：
   - 配置核心、锁、revision 与凭据生命周期；
   - Gateway、Runtime、CLI 与 TUI；
   - Desktop API、IPC、Renderer；
   - 测试、构建与发布脚本；
   - 用户手册、实施报告和本方案；
4. 每个提交运行最小相关测试，最终 commit 运行完整功能门禁；
5. 生成机器可读的门禁结果，记录 commit SHA、平台、工具版本和退出码；
6. 确认新增 `drsai/config` 模块、测试和验证脚本均被 Git 跟踪。

验收标准：

- 功能可从干净 checkout 构建和测试；
- `git status` 不包含遗漏的功能文件；
- 每项报告结果都能追溯到 commit SHA 和命令；
- 可以独立回退 Desktop 层而不破坏配置核心兼容性。

### 5.2 工作包 B：删除与恢复交互安全

用应用内三选项对话框替换 `window.confirm()`：

- 删除 Provider 和安全凭据；
- 仅删除 Provider，保留凭据；
- 取消，不做任何修改。

同时明确三个独立动作：

- 恢复 HepAI：只切换当前连接，不删除自定义 Provider；
- 删除 Provider：仅删除指定 Provider；若删除当前 Provider，再切换到 HepAI；
- 清理凭据：预览后显式执行，不隐式删除仍被当前或最后可用配置引用的凭据。

交互要求：

- 对话框展示 Provider 名称、是否为当前连接、凭据是否存在；
- 危险按钮使用明确动词，键盘 `Esc` 和关闭按钮必须等价于取消；
- 执行后显示实际结果，而不是预设成功文案；
- revision 冲突时不关闭对话框，提供重新加载和查看差异入口；
- 屏幕阅读器能识别标题、说明、按钮和危险级别。

### 5.3 工作包 C：Desktop 真实 UI E2E

采用 Electron E2E 测试驱动真实 Renderer、preload、main 和测试 Gateway。测试使用临时用户目录与临时配置，不读取开发者真实凭据。

必须覆盖的用户旅程：

1. 首次使用 DeepSeek 预设，输入 Key，测试成功并保存；
2. 错误 Key 测试失败，确认当前配置、revision 和凭据均未改变；
3. Ollama 无 Key 配置，模型发现、选择、保存并重启恢复；
4. 安全存储、环境变量、无 Key 三种来源切换时，只显示对应字段；
5. 手工输入未知模型，显示未校准提示但允许继续；
6. 两个窗口产生 revision 冲突，后保存者必须看到冲突并重新加载；
7. 删除当前 Provider：分别验证删除凭据、保留凭据和取消；
8. 恢复 HepAI 后，自定义 Provider 和凭据仍按用户选择保留；
9. 下一轮请求使用新配置，当前生成不被中断；
10. Gateway 不可用、超时或重启时，界面保持可恢复且不误报保存成功。

测试不变量：

- Renderer DOM、截图、日志和失败附件不得出现真实 Key；
- 每个场景结束后检查临时目录中的 TOML、last-good 和凭据引用；
- 测试失败时保留脱敏截图、Trace、Gateway 日志和 revision 变化记录；
- Windows 与 macOS 使用同一套场景定义，平台专属凭据断言单独实现。

### 5.4 工作包 D：macOS 发布门禁

在 macOS CI 或发布机生成签名并完成公证的应用产物，然后执行：

1. 安装与首次启动；
2. 保存、读取、替换和删除 Keychain 凭据；
3. 验证 Key 不出现在命令行参数、进程列表、日志或诊断包；
4. 验证 Renderer → preload → main → Gateway 配置链路；
5. 验证签名包中的 Python 后端模块、Provider 预设和验证脚本完整；
6. 配置 DeepSeek 或测试兼容服务，保存后重启应用；
7. 验证 last-good 恢复和凭据保留/删除；
8. 验证升级安装不会丢失既有 TOML 或 Keychain 项；
9. 验证应用卸载后的凭据保留策略符合产品说明。

门禁必须上传：

- 产物哈希、签名和公证结果；
- 脱敏测试报告；
- Keychain 生命周期断言；
- 应用重启和升级恢复结果。

任何一项失败都不得用 Windows 源码测试替代。

### 5.5 工作包 E：真实 Provider 兼容矩阵

建立两层测试：

- 每次提交：本地确定性模拟服务，不访问公网；
- 发布前或定时任务：使用专用低权限、低额度测试账号执行真实服务探测。

最低兼容矩阵：

| 服务类型 | basic | model | 模型发现 | 认证 | 必测边界 |
|---|---|---|---|---|---|
| OpenAI | 是 | 是 | 是 | Key | 401、429、模型不存在 |
| Anthropic | 是 | 是 | 可选 | Key | 版本 Header、最小请求费用 |
| DeepSeek | 是 | 是 | 是 | Key | OpenAI-compatible URL 拼接 |
| Ollama | 是 | 是 | 是 | 无 Key | 本地未启动、空模型列表 |
| 仅聊天兼容服务 | 是 | 是 | 不支持 | 可选 | `/models` 404 后回退 |
| 自定义代理服务 | 是 | 是 | 可选 | Key/自定义环境 | 代理、重写路径、超时 |

真实测试 Key 必须来自 CI Secret，禁止写入参数、Trace、测试报告或缓存。测试账号应设置额度上限；`model` 测试采用最小输出并记录预计费用等级，不记录响应正文。

### 5.6 工作包 F：测试基线与 flaky 治理

针对当前4项非本功能失败：

1. OAEP 生成物漂移：确认生成器是否应重跑；若是，提交生成物并加一致性门禁；若不是，修复错误基线；
2. Android 验收夹具：修复夹具或将其移动到明确的设备环境门禁，禁止静默忽略；
3. Codex 时序测试：连续或随机种子重复运行，记录失败率、进程残留和耗时分布；
4. 将“已知基线失败”和“本次新增失败”分开展示；新增失败必须阻断合并；
5. 禁止把 `passed` 数量单独表述为“全量通过”。

目标：发布分支最终实现全绿；如果确有外部环境阻塞，必须有负责人、问题链接、到期日和显式豁免。

### 5.7 工作包 G：状态表达与两级连接测试

Desktop、TUI 和 CLI 统一展示两种测试：

- 基础连接：优先检查 DNS、TLS、鉴权和服务端点，尽量不产生模型调用费用；
- 模型调用：对指定模型发起最小请求，明确提示可能产生费用。

状态卡至少区分：

- 未测试；
- 服务可连接；
- 模型已验证；
- 测试失败但当前运行配置未改变；
- 配置已保存、等待下一轮生效；
- 配置已生效；
- 新 Client 构建失败，仍使用旧配置。

测试结果应包含时间、模式、耗时、稳定错误码和脱敏建议，不保存响应正文。`basic` 成功不得显示成“模型调用成功”。

### 5.8 工作包 H：可观测性与灰度发布

- 仅记录脱敏分类计数：配置预览、提交、冲突、探测错误类别、恢复和 Client 切换结果；
- 不记录 Base URL、模型内容、Key、环境变量值或上游正文；
- 先在内部或小比例用户启用新的写入入口；
- 保留 `DRSAI_MODEL_CONFIG_WRITES=disabled` 紧急熔断；
- 监控配置成功率、测试失败后恢复率、冲突率、凭据错误率和 Client 回退率；
- 明确回滚版本对新 TOML、凭据引用和 last-good 文件的兼容性。

## 6. 实施阶段

### Phase 0：冻结基线与拆分交付（P0）

- 完成功能文件清单和提交拆分；
- 固化当前95项专项门禁；
- 建立全量测试的已知失败基线；
- 输出干净 checkout 的构建证据。

完成标准：任何开发者可以从指定 commit 重现专项验证结果。

### Phase 1：用户操作安全与 Desktop E2E（P0）

- 上线三选项删除对话框；
- 分离恢复、删除和凭据清理语义；
- 建立 Desktop E2E 基础设施；
- 完成10条关键用户旅程。

完成标准：关键操作均有真实 UI 自动化，取消操作绝不修改状态。

### Phase 2：macOS 与跨平台发布门禁（P0）

- 建立签名、公证、安装、升级和 Keychain 测试；
- 复用 Desktop E2E 场景；
- 将结果接入发布流水线。

完成标准：Windows 和 macOS 均在最终产物上通过同等配置旅程。

### Phase 3：真实兼容性与门禁清零（P1）

- 上线真实 Provider 定时/发布前矩阵；
- 治理4项已有失败和 Codex flaky；
- 完成两级测试与状态语义。

完成标准：发布分支全绿，真实 Provider 矩阵无阻塞性失败。

### Phase 4：灰度与发布（P2）

- 小范围灰度；
- 观察脱敏指标和用户恢复路径；
- 演练写入熔断和版本回退；
- 更新最终发布报告和用户手册。

完成标准：灰度期间无 Key 泄漏、配置损坏或不可恢复的 Client 切换事故。

## 7. 测试策略

### 7.1 每次提交

- 配置事务、凭据、Gateway、CLI、TUI 专项测试；
- Desktop node/web 类型检查；
- Provider/Secret 静态契约；
- 本地模拟 Gateway HTTP E2E；
- 与修改范围对应的 Desktop UI E2E 子集。

### 7.2 合并前

- 模型配置专项全量；
- Python 全量测试；
- Windows Desktop 生产构建与产物冒烟；
- Desktop UI E2E 全量；
- TUI 类型检查；
- Secret 扫描和生成物一致性检查。

### 7.3 发布前

- Windows 安装包和 macOS 签名公证包真实安装测试；
- 真实 Provider 兼容矩阵；
- 升级、重启、恢复和回滚演练；
- 凭据生命周期与诊断包 Secret 扫描；
- 失败基线为零，或具备正式且有期限的发布豁免。

## 8. 发布门禁

以下条件全部满足才允许宣称“跨平台发布就绪”：

- 所有交付文件已进入可审查提交，干净 checkout 可重现构建；
- 模型配置专项、Python 全量和 Desktop/TUI 类型检查无新增失败；
- Windows 与 macOS 最终产物均通过真实 UI 配置旅程；
- macOS Keychain 测试覆盖保存、读取、替换、保留、删除和损坏恢复；
- UI 的取消、测试失败和 revision 冲突均不修改有效配置；
- 真实 Provider 矩阵覆盖 OpenAI、Anthropic、DeepSeek、Ollama 和仅聊天兼容服务；
- 日志、Trace、截图、IPC、API、进程参数和诊断包通过 Secret 扫描；
- basic 与 model 测试的状态和费用提示不混淆；
- 写入熔断和版本回退至少演练一次；
- 用户手册、CLI help、TUI 和 Desktop 文案一致。

## 9. 验收指标

### 9.1 工程指标

- 干净 checkout 构建成功率：100%；
- 配置专项通过率：100%；
- 新增 flaky 测试：0；
- 并发修改静默丢失：0；
- 测试失败造成配置或凭据落盘：0；
- Secret 扫描发现明文 Key：0；
- Windows/macOS 最终产物关键旅程通过率：100%。

### 9.2 用户指标

- 常见 Provider 首次配置成功率不低于90%；
- 从打开设置到首次 basic 测试成功的中位时间低于3分钟；
- 用户选择取消后发生状态修改：0；
- basic 成功被误解为模型已实际调用的可用性测试事件：0；
- 配置错误后可通过建议自行恢复的比例不低于80%。

## 10. 风险与缓解

| 风险 | 影响 | 缓解措施 |
|---|---|---|
| 混合工作区导致错误提交 | 高 | 先做文件清单和提交拆分，不覆盖无关改动 |
| macOS CI 无签名权限 | 高 | 使用专用发布 Runner 和最小权限证书，设备门禁不得降级为源码测试 |
| 真实 Provider 测试产生费用或泄漏 Key | 高 | 低额度账号、CI Secret、最小请求、全链路脱敏 |
| Electron E2E 不稳定 | 中 | 临时用户目录、确定性测试 Gateway、等待可观察状态而非固定 sleep |
| Provider 协议变化 | 中 | 本地契约测试加定时真实矩阵，预设版本化 |
| 已有全量失败掩盖回归 | 中 | 已知失败基线与新增失败分栏，新增失败强制阻断 |
| 旧版本无法读取新状态 | 中 | 保持 TOML 向后兼容，发布前执行降级和回滚演练 |

## 11. 建议的首批开发任务

1. 输出模型配置功能文件清单并整理为可复现提交序列；
2. 将 Provider 删除改为三选项对话框，补取消零副作用测试；
3. 建立 Electron 临时用户目录和确定性测试 Gateway；
4. 自动化 DeepSeek、Ollama、revision 冲突、删除/恢复四条核心旅程；
5. 建立 macOS 签名产物安装及 Keychain 生命周期脚本；
6. 将 basic/model 两级测试和状态语义统一到 Desktop、TUI、CLI；
7. 修复或基线化 OAEP、Android 和 Codex 时序门禁；
8. 建立低额度真实 Provider 发布前矩阵；
