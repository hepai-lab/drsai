# LLM Space 对 OpenDrSai 的启发

## 1. 将一次运行定义为可重放实验

OpenDrSai 已有 runtime journal、协议事件和跨端执行基础。可以进一步形成稳定的“实验快照”概念，将以下内容绑定到同一个可追溯对象：

- Agent、模型和参数版本。
- System Prompt、Skill 和工具清单。
- 用户输入与消息轨迹。
- OAEP 标准化事件。
- 工具输入、输出、错误和审批。
- 运行环境及依赖版本。
- 评测结果和人工备注。

这比单纯保存聊天记录更接近科学任务所要求的可监督、可复现和可审计。

## 2. 基于事件的时间旅行调试

LLM Space 的“从某条消息继续运行”值得借鉴。OpenDrSai 可以基于 journal/OAEP 定义检查点，在不修改历史证据的前提下创建分支运行：

```text
原始运行 ── checkpoint N ── 原始后续轨迹
                    ├──── 修改 Prompt 后的分支
                    ├──── 替换模型后的分支
                    └──── 模拟 Tool Result 的分支
```

新分支应引用父运行和分叉点，而不是覆盖原始日志。

## 3. Tool Call 检查器

桌面端可以为标准化工具事件提供专用视图：

- schema 与实际参数的差异。
- 工具权限和审批状态。
- 调用耗时、重试、取消与错误分类。
- 原始数据与脱敏数据切换。
- 重新执行、复制参数、创建模拟返回值。

这可以直接服务 MCP、OpenAPI、HepAI Worker 和本地工具等多种执行器。

## 4. 对比评测而不是单次评分

LLM Space 的 A/B 运行对比很适合开发阶段。OpenDrSai 可以在此基础上扩展：

- 人工 rubric 与自动指标并存。
- 同一输入跨模型、Prompt、Skill 或 runtime 版本对比。
- 成本、时延、工具成功率和任务完成率统一呈现。
- 从单案例对比升级为数据集回归。
- 将评测结果关联到 `eval/` 中的 benchmark。

## 5. 本地优先、远程可执行

LLM Space 的本地 Thread 与 OpenDrSai 的远程 workspace、relay 和跨设备能力可以形成互补设计：控制界面和敏感实验元数据可留在本地，实际任务可以运行在远程科研环境；二者通过标准事件协议连接。

## 不宜直接照搬

- 不引入第二套 Agent loop 替换 OpenDrSai runtime。
- 不将 Thread JSON 直接作为 OpenDrSai 的跨端协议。
- 不把仅支持人工评分的功能包装成完整 Agent 自动调优。
- 不将桌面 UI 状态与运行时权威状态绑定在同一不可迁移文件中。
- 不默认允许重放产生外部副作用的工具调用。

## 可形成的差异化能力

OpenDrSai 面向科学智能体，可在通用 Agent 调试器之上增加：

- 科学数据、计算环境和结果产物的 provenance。
- 长任务断点、恢复、守护和跨设备接管。
- 多 Agent 团队的因果轨迹与消息拓扑。
- 高风险工具的审批、沙箱和可重放策略。
- OAEP 驱动的跨 runtime、跨客户端一致调试。
- benchmark、真实运行和人工评审之间的统一证据链。
