# OpenDrSai 用户需求清单

## 1. 文档用途

本文记录未来需要面向真实用户提供的功能需求，作为产品设计、开发排期和后续测试设计的统一清单。

本清单独立于 `eval/regression/` 当前已有的 12 项智能体回归测试：需求在功能、测试账号、外部环境和验收标准准备完成前，不进入现有回归套件，也不计入当前发布门禁。后续某项具备稳定、可重复、可审计的自动化条件后，再将其转化为正式测试用例。

## 3. 转为正式测试前需补齐的信息

每个候选项进入自动化或人工验收前，至少补齐：

- 准确的测试环境地址、账号类型和授权方式；
- 可安全读取、修改或预定的专用测试数据；
- 用户输入、前置条件、操作步骤和预期结果；
- 对外部系统产生副作用时的确认、幂等和清理策略；
- 成功、失败、权限不足、会话过期、冲突和断网等验收标准；
- 证据保存与脱敏要求，包括截图、操作轨迹、结果记录和外部系统回执；
- 是否纳入 `eval/regression/`、独立端到端套件或仅作为受控人工验收。

## 4. 维护约定

- 新的用户需求按 `UFT-###` 顺序编号并追加到本清单。
- “待设计”表示仅记录产品目标，不代表功能已经实现或测试已经通过。
- 测试不得使用真实业务文档或真实会议预定产生不可控影响；正式执行前应使用隔离账号和可清理的测试资源。
- 外部站点界面或接口变化时，应更新用例版本并重新验证，不能沿用旧证据直接判定通过。
