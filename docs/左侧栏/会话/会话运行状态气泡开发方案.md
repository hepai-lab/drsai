# 左侧栏会话运行状态气泡开发方案

状态：已完成
日期：2026-07-29

## 1. 背景

左侧栏的会话条目右侧目前始终显示最后更新时间。用户无法在不打开会话的情况下判断：

- 哪些会话仍在运行；
- 哪些会话正在等待批准；
- 哪些会话正在等待用户输入、选择或确认；
- 会话何时已经停止并恢复为普通历史记录。

本功能需要在不增加额外文字、不改变会话条目高度、不造成标题跳动的前提下，把会话的实时状态呈现在时间位置。

## 2. 目标

### 2.1 核心效果

| 会话状态 | 条目右侧表现 |
|---|---|
| 已停止、已完成、空闲或失败 | 显示最后更新时间 |
| 正在正常运行 | 显示淡色动态旋转气泡 |
| 等待批准 | 显示彩色动态旋转气泡 |
| 等待输入、选择或确认 | 显示彩色动态旋转气泡 |

状态切换必须自动完成：

```text
时间 -> 淡色气泡 -> 彩色气泡 -> 淡色气泡 -> 时间
```

例如，Agent 开始运行后显示淡色气泡；执行到审批步骤时切换为彩色气泡；批准后恢复淡色气泡；任务结束后恢复时间。

### 2.2 非目标

第一版不包含：

- 在气泡内显示任务进度百分比；
- 使用气泡替代审批中心或会话内交互界面；
- 点击气泡弹出独立菜单；
- 为错误状态增加第三套动画；
- 在左侧栏展示运行步骤文字。

## 3. 现有实现

### 3.1 会话模型

`DesktopThread` 位于：

```text
apps/desktop/shared/api/desktopApi.ts
```

当前已有：

```ts
status?: "idle" | "running" | "error";
lastRunId?: string;
lastRequestId?: string;
runtimeSessionId?: string;
```

`status` 可以提供基础运行状态，但无法表达“运行中且等待用户处理”。

### 3.2 消息快照

`DesktopThreadSnapshot` 和结构化消息已经能够表达：

- `message.streaming`；
- `structuredTurn.status === "pending" | "running"`；
- 未完成的 `inputRequest`；
- `approval`、`text_input`、`choice`、`confirmation` 交互类型。

这部分可以直接用于识别会话内等待交互。

### 3.3 后台任务

`DesktopBackgroundTask` 已经包含：

```ts
status: "queued" | "running" | "waiting_approval" | ...;
targetId?: string;
approvalId?: string;
pendingDecisions?: string[];
```

当前后台任务与会话主要通过以下字段进行间接关联：

```text
thread.lastRunId     <-> task.targetId
thread.lastRequestId <-> task.targetId
```

这种关联可以用于兼容旧数据，但长期应增加明确的 `threadId`。

### 3.4 左侧栏条目

`WorkspaceThread` 和条目渲染位于：

```text
apps/desktop/shared/renderer/src/components/WorkspaceShell.tsx
```

当前右侧直接渲染：

```tsx
<time>{thread.timeLabel}</time>
```

样式位于：

```text
apps/desktop/shared/renderer/src/styles.css
```

条目使用两列布局，右侧列已经适合替换为固定宽度的状态槽。

## 4. 状态模型

### 4.1 界面状态

新增仅供渲染层使用的类型：

```ts
export type ThreadActivityState =
  | {
      kind: "idle";
    }
  | {
      kind: "running";
    }
  | {
      kind: "attention";
      reason: "approval" | "interaction";
    };
```

`ThreadActivityState` 不写入 `threads.json`。它必须由当前线程、消息快照和后台任务实时推导，避免应用异常退出后留下永久旋转的气泡。

扩展 `WorkspaceThread`：

```ts
export interface WorkspaceThread {
  id: string;
  title: string;
  timeLabel: string;
  activity: ThreadActivityState;
  // existing fields...
}
```

### 4.2 状态优先级

状态判定采用以下固定优先级：

```text
等待批准 > 等待其他交互 > 正在运行 > 空闲
```

具体规则：

#### 等待批准

满足任意一项：

- 后台任务 `status === "waiting_approval"`；
- 后台任务存在 `approvalId`；
- 后台任务存在未完成的 `pendingDecisions`；
- 最新未完成 `inputRequest.inputType === "approval"`。

结果：

```ts
{ kind: "attention", reason: "approval" }
```

#### 等待其他交互

最新结构化消息存在尚未答复的：

- `text_input`；
- `choice`；
- `confirmation`。

结果：

```ts
{ kind: "attention", reason: "interaction" }
```

#### 正在运行

满足任意一项：

- `thread.status === "running"`；
- 消息快照中存在 `message.streaming === true`；
- 结构化回合状态为 `pending` 或 `running`；
- 关联后台任务状态为 `running`。

结果：

```ts
{ kind: "running" }
```

#### 空闲

不满足以上条件时：

```ts
{ kind: "idle" }
```

`queued` 第一版不显示旋转气泡。排队尚未开始执行，仍显示时间，避免用户误认为 Agent 已经在消耗计算资源。

### 4.3 纯状态推导函数

新增：

```text
apps/desktop/shared/renderer/src/threadActivity.ts
```

建议接口：

```ts
export function deriveThreadActivity(input: {
  thread: DesktopThread;
  snapshot?: DesktopThreadSnapshot;
  backgroundTask?: DesktopBackgroundTask;
}): ThreadActivityState;
```

该函数必须是无副作用的纯函数，所有状态优先级测试集中写在这里。

## 5. 会话与后台任务关联

### 5.1 第一版兼容策略

建立一次性的任务索引：

```ts
Map<string, DesktopBackgroundTask>
```

按以下顺序查找任务：

1. `task.threadId === thread.id`；
2. `task.targetId === thread.lastRequestId`；
3. `task.targetId === thread.lastRunId`。

如果同一会话匹配多个任务，优先选择：

1. `waiting_approval`；
2. `running`；
3. `queued`；
4. 更新时间最新的任务。

禁止在每个会话条目中单独调用 `listBackgroundTasks`。

### 5.2 正式关联字段

为 `DesktopBackgroundTask` 增加：

```ts
threadId?: string;
```

新增后台任务时，如果任务属于某个会话，必须写入 `threadId`。旧数据继续通过 `targetId` 回退匹配。

涉及文件预计包括：

```text
apps/desktop/shared/api/desktopApi.ts
apps/desktop/shared/main/backgroundTasks.ts
apps/desktop/shared/renderer/src/mockDesktopApi.ts
各后台任务 enqueue 调用位置
```

### 5.3 状态同步

推荐采用“事件驱动 + 低频校准”：

1. 应用启动时调用一次 `listBackgroundTasks`；
2. 主进程在后台任务发生变化时发送 `desktop:background-task-changed`；
3. preload 暴露 `onBackgroundTaskChanged`；
4. `App.tsx` 更新统一的后台任务状态；
5. 每 15 秒进行一次列表校准；
6. 窗口不可见时暂停校准，恢复可见时立即刷新。

如果第一版暂不增加 IPC 事件，可以先在 `App.tsx` 中集中每秒轮询一次，但不得在多个组件中重复轮询。

## 6. 气泡组件

新增：

```text
apps/desktop/shared/renderer/src/components/ThreadActivityBubble.tsx
```

建议接口：

```ts
export interface ThreadActivityBubbleProps {
  state: Exclude<ThreadActivityState, { kind: "idle" }>;
  language: AppLanguage;
}
```

组件只负责展示，不负责读取线程、审批或后台任务数据。

渲染结构：

```tsx
<span
  className={`thread-activity-bubble ${state.kind} ...`}
  role="status"
  aria-label={label}
  title={label}
>
  <i />
  <i />
  <i />
</span>
```

提示文字：

| 状态 | 中文 | 英文 |
|---|---|---|
| 普通运行 | 正在运行 | Running |
| 等待批准 | 等待批准 | Approval required |
| 等待交互 | 等待回复 | Response required |

不要使用 `aria-live`，否则每次状态刷新可能反复打断屏幕阅读器。

## 7. 视觉规格

### 7.1 右侧状态槽

时间和气泡共用固定区域：

```css
.thread-item-status {
  width: 44px;
  min-width: 44px;
  display: inline-flex;
  align-items: center;
  justify-content: flex-end;
}
```

目标：

- 状态切换时标题不左右移动；
- 长标题仍然省略；
- 条目高度保持 29px；
- 气泡不会改变网格列宽。

### 7.2 普通运行气泡

- 容器：16px × 16px；
- 3 个圆点：3px、4px、3px；
- 使用灰蓝色或当前主题的弱强调色；
- 透明度范围：`0.25–0.55`；
- 旋转周期：`1.8s`；
- 动画：匀速旋转，附带轻微透明度变化；
- 不使用渐变。

建议颜色变量：

```css
--thread-running-bubble: #8fa1b5;
```

暗色主题单独提高亮度和透明度。

### 7.3 待处理气泡

- 几何尺寸与普通气泡完全一致；
- 三个圆点分别使用青色、黄色和玫红色；
- 旋转周期：`1.25s`；
- 增加幅度很小的呼吸效果；
- 不改变条目背景；
- 不持续闪烁，不使用高亮白色描边。

建议颜色：

```css
--thread-attention-cyan: #22b8cf;
--thread-attention-yellow: #f2b84b;
--thread-attention-rose: #e56b91;
```

### 7.4 减少动态效果

必须支持：

```css
@media (prefers-reduced-motion: reduce)
```

此时：

- 停止旋转和呼吸；
- 保留三个静态圆点；
- 仍通过颜色区分普通运行和待处理状态。

## 8. 左侧栏渲染改动

在 `renderWorkspaceThread` 中将：

```tsx
<time>{thread.timeLabel}</time>
```

替换为：

```tsx
<span className="thread-item-status">
  {thread.activity.kind === "idle" ? (
    <time>{thread.timeLabel}</time>
  ) : (
    <ThreadActivityBubble
      state={thread.activity}
      language={language}
    />
  )}
</span>
```

会话条目整体仍是唯一的点击目标。点击任何位置，包括气泡区域，都进入对应会话。

第一版不改变点击行为：

- 等待会话内交互时，进入会话后直接看到交互卡片；
- 等待后台审批时，进入会话后保留现有审批入口；
- 不因为点击彩色气泡直接跳转审批中心。

## 9. App 状态聚合

`App.tsx` 增加：

```ts
const [backgroundTasks, setBackgroundTasks] =
  useState<DesktopBackgroundTask[]>([]);
```

通过 `useMemo` 生成任务索引：

```ts
const backgroundTaskByThreadId = useMemo(
  () => indexBackgroundTasksByThread(threads, backgroundTasks),
  [threads, backgroundTasks],
);
```

构建 `recentThreads`、`searchableThreads` 和 `workspaceThreads` 时统一调用：

```ts
activity: deriveThreadActivity({
  thread,
  snapshot: threadSnapshots[thread.id],
  backgroundTask: backgroundTaskByThreadId.get(thread.id),
}),
```

禁止三个列表分别实现一套状态判断。建议抽取：

```ts
function toWorkspaceThread(
  thread: DesktopThread,
  context: ThreadPresentationContext,
): WorkspaceThread;
```

这样可以同时消除当前三处重复映射逻辑。

## 10. 状态恢复与竞态

### 10.1 应用重启

启动后：

1. 读取线程列表；
2. 读取线程快照；
3. 读取后台任务；
4. 完成状态推导；
5. Runtime 目录同步到达后再次修正。

在后台任务尚未加载时，可以临时使用 `thread.status`，但任务加载完成后必须以完整推导结果覆盖。

### 10.2 任务完成竞态

任务完成事件和最后一条消息快照可能先后到达。状态优先采用：

- 未处理交互请求仍存在：保持彩色气泡；
- 否则后台任务完成且没有流式消息：恢复时间；
- 流式消息超过恢复超时仍未结束：由现有流恢复逻辑负责修正，不在气泡组件中设置计时器。

### 10.3 已归档会话

已归档会话不出现在默认左侧栏，因此无需显示气泡。设置中的归档会话列表继续显示时间或归档信息，不复用运行气泡。

### 10.4 错误状态

`thread.status === "error"` 且没有运行或等待交互信号时显示时间。错误详情仍在会话内呈现，第一版不新增红色气泡。

## 11. 测试方案

### 11.1 状态推导单元测试

新增：

```text
apps/desktop/windows/scripts/verify-thread-activity.mts
```

至少覆盖：

1. 空闲线程返回 `idle`；
2. `thread.status=running` 返回 `running`；
3. 流式消息返回 `running`；
4. 后台任务 `running` 返回 `running`；
5. `waiting_approval` 覆盖 `running`；
6. `approvalId` 覆盖 `running`；
7. `pendingDecisions` 覆盖 `running`；
8. approval input request 返回 `attention/approval`；
9. choice input request 返回 `attention/interaction`；
10. 任务完成且消息停止后返回 `idle`；
11. 错误线程返回 `idle`；
12. 多任务匹配时使用最高优先级任务；
13. `threadId` 优先于旧 `targetId` 映射。

### 11.2 组件测试

覆盖：

- 空闲时只显示时间；
- 运行时隐藏时间并显示普通气泡；
- 待批准时显示彩色气泡；
- 待回复时显示彩色气泡；
- `title` 和 `aria-label` 正确；
- 气泡不是额外按钮；
- 状态切换不改变条目宽度和高度。

### 11.3 视觉测试

至少生成以下截图：

- 浅色主题：空闲、运行、等待批准混合列表；
- 深色主题：空闲、运行、等待批准混合列表；
- 窄侧栏和超长中文标题；
- 当前选中、悬停、未读和置顶状态叠加；
- 一个工作区中同时有多个运行会话；
- 减少动态效果模式。

需要检查：

- 标题不被气泡遮挡；
- 气泡不与时间位置发生跳动；
- 彩色气泡在浅色和深色背景下都可辨认；
- 滚动时动画不抖动；
- 气泡不会扩大条目高度。

### 11.4 集成测试

端到端状态流：

```text
创建会话
-> 发送任务
-> 出现普通气泡
-> Agent 请求批准
-> 出现彩色气泡
-> 用户批准
-> 恢复普通气泡
-> Agent 完成
-> 恢复时间
```

同时验证非当前会话：

1. 启动会话 A；
2. 切换到会话 B；
3. 会话 A 继续显示运行气泡；
4. 会话 A 请求交互后变为彩色；
5. 会话 A 完成后恢复时间。

### 11.5 性能测试

- 200 条会话列表；
- 同时 20 条显示运行气泡；
- 连续滚动 30 秒；
- 动画只修改 `transform` 和 `opacity`；
- 不因每个气泡创建独立 JavaScript 定时器；
- 后台任务只进行一次集中索引，不允许每行重复遍历完整任务数组。

## 12. 开发步骤

### 阶段一：状态基础

1. 新建 `threadActivity.ts`；
2. 定义 `ThreadActivityState`；
3. 实现状态优先级；
4. 实现后台任务到会话的索引；
5. 完成纯函数单元测试。

完成标准：所有状态输入都能稳定推导为 `idle/running/attention`。

### 阶段二：左侧栏视觉

1. 扩展 `WorkspaceThread`；
2. 新增 `ThreadActivityBubble`；
3. 增加固定右侧状态槽；
4. 增加普通和彩色气泡动画；
5. 支持明暗主题和减少动态效果；
6. 完成组件与视觉测试。

完成标准：模拟状态可以正确切换时间和气泡，布局无跳动。

### 阶段三：真实状态接入

1. `App.tsx` 集中读取后台任务；
2. 接入线程快照；
3. 接入 `thread.status`；
4. 为后台任务增加 `threadId`；
5. 保留 `targetId` 兼容逻辑；
6. 增加 IPC 任务变更事件或集中轮询。

完成标准：当前和非当前会话都能实时显示真实运行状态。

### 阶段四：恢复与发布门禁

1. 验证重启恢复；
2. 验证网络中断和 Runtime 重连；
3. 验证等待批准后恢复运行；
4. 验证后台任务完成竞态；
5. 完成 Windows 构建、类型检查和 UI 回归。

完成标准：不存在永久旋转、提前消失或错误变色的状态。

## 14. 验收标准

- 会话开始运行后 1 秒内，时间替换为淡色旋转气泡；
- 非当前会话同样能够显示运行状态；
- 等待批准或回复后 1 秒内切换为彩色气泡；
- 用户完成批准或回复后，彩色气泡恢复为淡色气泡；
- 会话停止后 1 秒内恢复显示时间；
- 应用重启后不会出现没有真实任务的永久气泡；
- 时间和气泡切换时标题位置不变化；
- 明暗主题、窄侧栏、长标题下无重叠；
- 减少动态效果模式下气泡静止但状态可辨认；
- 运行状态不会依赖当前打开哪个会话；
- 归档、置顶、未读和工作区折叠行为不受影响；
- 类型检查、行为测试、视觉测试和 Windows 构建全部通过。

## 15. 推荐实施范围

建议一次完成阶段一至阶段四，不只提交静态动画。单独实现气泡视觉会造成“当前会话看起来正常、后台会话状态错误”的问题。

整体开发量为中等，主要工作不在动画，而在统一运行状态、后台任务关联和重启恢复。视觉组件本身可以保持很小，状态推导与任务关联应作为本功能的核心。
