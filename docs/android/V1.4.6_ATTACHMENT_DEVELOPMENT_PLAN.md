# OpenDrSai Android v1.4.6 附件功能开发计划

状态：开发联调中（62/66 完成，1 项进行中，1 项外部设备阻塞，2 项待发布）
目标版本：v1.4.6
目标产物：`OpenDrSai-Android-v1.4.6.apk`
生产环境：`https://ai.ihep.ac.cn`
开发环境：`https://ai-dev.ihep.ac.cn`

## 1. 目标与完成定义

v1.4.6 为 Android 聊天增加完整的附件闭环：用户点击输入框左侧加号，可以拍照、从相册选择图片或从系统文件选择器选择文件；附件经过本地校验、预处理和 OIDC 鉴权上传后，与消息一起发送给 Android 本机 OpenDrSai Runtime 或 HAI 平台智能体；智能体必须能够读取附件实际内容并完成处理，历史消息能够恢复附件，智能体生成的结果文件能够下载和打开。

“完成附件功能”必须同时满足：

1. 能选择附件，而不是仅显示入口；
2. 能上传附件字节，而不是仅发送手机路径或文件名；
3. 服务端能验证附件属于当前 OIDC 用户；
4. Agent 能读取图片、文本或 PDF 的真实内容；
5. 失败后能够重试，历史中能够恢复，临时文件能够清理；
6. 开发环境与生产环境真机验收均通过。

## 2. 范围与限制

### 2.1 v1.4.6 支持

- 来源：拍照、系统相册、系统文件选择器；
- 图片：JPEG、PNG、WebP；
- 文本：TXT、Markdown、CSV、JSON、XML、YAML、LOG；
- 文档：PDF；
- 单次最多 5 个附件；
- 单文件最大 10 MB；
- 单次发送附件总大小最大 25 MB；
- 图片上传前最长边限制为 4096 像素；
- 允许只发送附件；传输层补充默认指令“请分析这些附件”；
- Android 本机 OpenDrSai 与声明支持附件的 HAI 平台智能体均可处理；
- 支持智能体结果文件的展示、下载和系统打开。

### 2.2 暂不支持

- 视频和音频附件；
- ZIP、RAR、APK、可执行文件；
- 文件夹上传；
- DOCX、XLSX、PPTX 的完整内容解析；
- 后台断点续传和跨进程持续上传；
- 图片裁剪、标注和编辑；
- 任意数量或任意大小的附件；
- 跨设备同步附件历史。

## 4. 详细开发项

### A. 产品边界与协议基线（5 个）

- [x] **A01** 固化 v1.4.6 支持的来源、格式、数量、大小和图片尺寸限制。
- [x] **A02** 定义附件状态机：`selected → preparing → ready → uploading → uploaded → sending → sent`，以及 `failed/cancelled/expired` 分支。
- [x] **A03** 定义 Agent 能力字段：`attachment-upload`、`image-input`、`document-input`、`artifact-output`。
- [x] **A04** 定义 Native API 的附件 ID 契约，禁止在聊天请求中传递 Android URI、客户端路径或服务端内部路径。
- [x] **A05** 定义向后兼容策略：服务端未声明附件能力时禁用附件发送，纯文本聊天保持 v1.4.5 行为。

### B. Android 选择与输入交互（8 个）

- [x] **B01** 点击加号打开 Material 3 底部菜单，显示“拍照、从相册选择、选择文件”。
- [x] **B02** 使用 `ActivityResultContracts.TakePicture` 和 `FileProvider` 完成系统相机拍照。
- [x] **B03** 使用 Android Photo Picker 选择图片，并处理旧系统兼容回退。
- [x] **B04** 使用 `ActivityResultContracts.OpenDocument` 选择受支持的文本文件和 PDF。
- [x] **B05** 在输入框上方显示附件草稿区：图片缩略图、文件名、类型、大小和状态。
- [x] **B06** 支持从草稿区删除、取消和对失败附件单独重试。
- [x] **B07** 支持仅附件发送；没有文字时由传输层生成默认处理指令。
- [x] **B08** 保持现有浮动输入框和 `adjustResize` 行为，键盘弹出后输入框贴近键盘且聊天内容同步上移。

### C. Android 文件预处理（7 个）

- [x] **C01** 将外部 `content://` 内容流式复制到应用私有缓存，后续不依赖短期 URI 授权。
- [x] **C02** 从 `ContentResolver` 获取并净化文件名、声明 MIME、大小等元数据。
- [x] **C03** 结合文件头、扩展名和 MIME 校验实际类型，拒绝不支持或伪装文件。
- [x] **C04** 在读取过程中执行单文件和总大小限制，避免一次性把完整文件读入内存。
- [x] **C05** 为文件流式计算 SHA-256，用于完整性校验、幂等和重复文件识别。
- [x] **C06** 对图片降采样、旋转纠正、最长边限制和压缩，并生成独立缩略图。
- [x] **C07** 定义缓存目录、文件命名和启动时恢复规则，处理选择后旋转屏幕或 Activity 重建。

### D. Android 上传与任务控制（7 个）

- [x] **D01** 实现 `AttachmentRepository` 和 Native Attachment API 客户端。
- [x] **D02** 通过 OIDC Bearer Token 逐文件执行 multipart 上传，Token 过期时只刷新并重试一次。
- [x] **D03** 提供逐附件上传进度，并把进度实时映射到附件草稿 UI。
- [x] **D04** 限制最多两个附件并发上传，避免移动网络和内存峰值。
- [x] **D05** 支持上传取消、网络失败重试和移除已上传但未发送的附件。
- [x] **D06** 为上传和聊天使用稳定的客户端请求 ID/幂等键，防止重试产生重复对象或重复 Run。
- [x] **D07** 所有附件上传成功后才提交聊天；部分失败时保留文字和全部附件草稿，不创建半成品用户消息。

### E. HAI Native 附件服务（9 个）

- [x] **E01** 新增 `POST /api/native/v1/attachments`，从 OIDC Token 获取用户身份并接收单文件 multipart 上传。
- [x] **E02** 新增标准上传响应：附件 ID、名称、kind、MIME、大小、SHA-256、处理状态和过期时间。
- [x] **E03** 新增 `DELETE /api/native/v1/attachments/{id}`，仅允许所有者删除未使用或可清理附件。
- [x] **E04** 新增 `GET /api/native/v1/attachments/{id}/context`，向 Android 本机 Runtime 返回受限的安全提取结果。
- [x] **E05** 使用用户隔离的 GFS 路径保存原始附件，禁止使用客户端文件名直接拼接存储路径。
- [x] **E06** 建立附件元数据和所有权记录，聊天时按当前 OIDC 用户、thread、run 验证附件 ID。
- [x] **E07** 实现图片、UTF-8 文本和 PDF 的安全识别与内容预处理，限制 PDF 页数及提取字符数。
- [x] **E08** 在 Agent Run 前把合法附件物化到受控临时目录，运行结束后清理临时副本。
- [x] **E09** 在 Native Catalog 暴露附件能力，并实现未就绪、过期、越权、超限和不支持格式的标准错误码。

## 5. Native API 目标契约

### 5.1 上传

```http
POST /api/native/v1/attachments
Authorization: Bearer <OIDC access token>
Content-Type: multipart/form-data

file=<binary>
thread_id=<uuid>
run_id=<uuid>
```

```json
{
  "status": true,
  "data": {
    "id": "att_01...",
    "name": "report.pdf",
    "kind": "file",
    "mime_type": "application/pdf",
    "size": 182736,
    "sha256": "...",
    "processing_status": "ready",
    "expires_at": "2026-07-16T12:00:00Z"
  }
}
```

### 5.2 聊天

```http
POST /api/native/v1/agents/{agent_id}/chat
Authorization: Bearer <OIDC access token>
Content-Type: application/json
```

```json
{
  "messages": [
    {"role": "user", "content": "帮我分析这份报告"}
  ],
  "stream": true,
  "thread_id": "...",
  "run_id": "...",
  "attachments": [
    {"id": "att_01..."}
  ]
}
```

聊天接口只信任附件 ID。名称、路径、URL、MIME、大小和所有权必须由服务端重新查询。

### 5.3 建议错误码

| HTTP | code | 含义 |
|---:|---|---|
| 400 | `unsupported_attachment_type` | 不支持的格式 |
| 400 | `attachment_not_ready` | 附件尚未处理完成 |
| 401 | `token_expired` | OIDC Token 过期，可刷新一次 |
| 403 | `attachment_forbidden` | 附件不属于当前用户或无权使用 |
| 404 | `attachment_not_found` | 附件不存在或已过期 |
| 413 | `attachment_too_large` | 单文件或总大小超限 |
| 422 | `attachment_invalid` | 文件头、MIME 或内容非法 |
| 429 | `attachment_rate_limited` | 上传频率或配额受限 |
| 503 | `attachment_storage_unavailable` | GFS/存储暂不可用 |

## 6. 实施顺序与依赖

```text
A 协议基线
├─ E Native 附件服务 ─┬─ D Android 上传
│                    └─ F Agent 集成
├─ B 选择与交互 ─ C 文件预处理 ─ D Android 上传
```

建议按以下里程碑执行：

1. **M1 协议闭环**：A、E 完成，使用命令行能上传附件并让开发环境平台 Agent 读取；

3. **M3 双 Runtime 处理**：F 完成，本机和平台 Agent 均能处理支持格式；
4. **M4 历史与安全**：G、H 完成，附件可恢复、可清理、用户隔离；
5. **M5 测试发布**：I、J 完成，产出并发布 v1.4.6 APK。

## 8. 预计工作量与主要风险

预计工作量为 8～12 个开发日。主要风险依次是：

1. Native API 当前只有附件元数据入口，尚未形成字节上传和所有权闭环；
2. 平台 Agent 和 Android 本机 Runtime 对附件的消费方式不同，需要统一领域模型但使用不同适配器；
3. 视觉模型的多模态请求格式与 HAI 当前模型能力必须先在开发环境确认；
4. PDF、超大图片和多附件容易造成内存峰值，必须坚持流式读取和限制；
5. 生产发布依赖 HAI Native 附件接口和存储配置先部署并完成能力声明。
