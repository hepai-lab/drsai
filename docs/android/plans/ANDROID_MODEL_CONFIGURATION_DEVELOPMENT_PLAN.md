# OpenDrSai Android 模型配置开发方案

## 1. 文档目的

本文定义 OpenDrSai Android 模型配置能力的产品目标、技术方案、模块边界、功能清单、测试策略和验收标准。它既用于指导后续开发，也用于约束数据库升级、安全存储、运行时路由和发布验收，避免出现“界面已保存但运行时未生效”“提供方重命名后历史会话失效”“密钥进入普通数据库或日志”等问题。

本文覆盖：

- 设置入口与分组导航；
- 模型提供方预设、自定义提供方和编辑流程；
- 一个提供方配置 N 个模型；
- 模型发现、手动维护、批量管理及启用状态；
- 默认模型选择与会话绑定；
- Room 持久化、Android Keystore 加密凭据和旧数据迁移；
- OpenAI Compatible、Anthropic 与 HepAI 运行时路由；
- 自动化测试、真机测试、升级测试和安全验收。

## 2. 总体目标

### 2.1 产品目标

1. 用户可以从 Android 主界面左侧栏底部进入结构化设置页。
2. 设置页在平板上使用“左侧分组导航 + 右侧内容”，在手机上使用可下钻列表。
3. 用户可以从预设创建 HepAI、OpenAI、Anthropic、DeepSeek、Ollama 提供方，也可以创建自定义提供方。
4. 自定义提供方允许修改显示名称、API 主机和协议；名称变化不得改变内部身份。
5. 一个提供方可以保存任意数量模型，并允许逐模型启用、停用、编辑能力或删除。
6. 用户可以从提供方获取模型，也可以手动新建模型；获取操作不得静默删除手工模型。
7. 保存必须具有明确的处理中、成功和失败反馈，应用重启及版本升级后配置仍然存在。
8. 只有启用模型进入聊天模型选择和运行时；停用模型仍保留在配置中。
9. API Key 不进入 Room、日志、诊断信息、Compose 状态快照或备份。
10. 新配置保存后立即对新会话生效，历史会话仍能通过稳定 ID 解析其模型。

### 2.2 工程目标

- 提供方和模型使用不可变 UUID，不使用显示名称或 `provider/model` 拼接字符串作为主键。
- 元数据使用 Room 事务保存；密钥使用 Android Keystore 支持的加密存储。
- 数据库迁移可前向升级且不破坏当前会话、模型选择和登录状态。
- 运行时通过稳定模型 ID 解析提供方、真实上游模型 ID、协议和凭据。
- OpenAI Compatible 与 Anthropic 采用独立 wire adapter，UI 不感知协议报文差异。
- 所有破坏性操作均可确认或撤销，所有长操作均有可观察状态。

## 3. 非目标与边界

本阶段不包括：

- 在 Android 端同步 Windows 的本地环境变量密钥；
- 将 API Key 上传到 HepAI、远程 Runtime 或云端；
- 自动判断任意私有服务的计费策略；
- 在无用户确认时执行可能产生费用的模型测试调用；
- 自动修改已有会话绑定的模型；
- 为每个第三方提供方实现其全部私有扩展参数。

远程工作区会话仍由远程 Runtime 的模型配置负责；本文的本地提供方配置只控制 Android 本地 Agent Runtime。

## 4. 当前问题与设计原则

### 4.1 需要解决的问题

- 模型切换曾隐藏在个人中心，缺少独立设置层级。
- 早期实现把提供方列表和 API Key 混合保存在加密 SharedPreferences JSON 中，缺少结构化迁移和事务。
- 早期运行时依赖拼接模型字符串，提供方重命名可能破坏引用。
- 保存结果位于长列表底部，模型多时用户看不到反馈。
- 获取大量模型后缺少搜索、批量启停和一次清理能力。
- 配置列表和运行时可用列表没有分离，导致停用模型无法继续编辑。
- 模型发现可能覆盖用户手工维护的模型。
- 缺少独立的连接检查、费用提示、未保存离开保护及模型变化摘要。

### 4.2 设计原则

- **身份与显示分离**：ID 永久稳定，名称可以编辑。
- **草稿与正式配置分离**：获取、编辑和检查不自动落盘。
- **元数据与密钥分离**：Room 只保存凭据引用或“已配置”状态。
- **配置与运行时分离**：配置保留全部模型，运行时只读取启用模型。
- **安全默认**：不回填明文密钥，不记录请求 Authorization，不暴露模型推理链。
- **明确反馈**：保存、获取、检查和删除均显示状态及下一步行动。
- **无静默丢失**：同步和批量操作必须保留手工配置或展示变化摘要。

## 5. 总体解决方案

### 5.1 分层结构

```text
Compose 设置界面
    ↓ Draft / UiState
AppViewModel
    ↓
ModelProviderRepository
    ├── Room: Provider / Model 元数据
    └── Encrypted credential store: API Key
    ↓ stable model ID
ModelGateway / wire adapters
    ├── HepAI OIDC
    ├── OpenAI Compatible
    └── Anthropic
```

### 5.2 核心数据模型

`ModelProviderEntity`：

| 字段 | 用途 |
| --- | --- |
| `id` | 不可变提供方 UUID；HepAI 使用保留 ID |
| `presetId` | 预设来源，如 `openai`、`anthropic`、`custom` |
| `displayName` | 用户看到的名称；自定义提供方可修改 |
| `baseUrl` | 规范化后的 API 主机 |
| `wireApi` | `openai` 或 `anthropic` |
| `builtIn` | 是否为不可删除内置项 |
| `enabled` | 提供方是否参与配置加载 |
| `revision` | 乐观并发控制版本 |
| `createdAt/updatedAt` | 审计和排序时间 |

`ProviderModelEntity`：

| 字段 | 用途 |
| --- | --- |
| `id` | 不可变模型配置 UUID |
| `providerId` | 所属提供方稳定 ID |
| `upstreamId` | 发给上游 API 的真实模型 ID |
| `displayName` | 用户可读名称 |
| `vision/tools/reasoning` | 模型能力声明 |
| `contextTokens/maxOutputTokens` | 上下文与输出限制 |
| `enabled` | 是否进入运行时模型列表 |
| `source` | `PRESET`、`DISCOVERED` 或 `MANUAL` |
| `sortOrder` | UI 排序 |

默认模型保存稳定的模型配置 ID。会话创建时记录模型 ID；提供方名称和模型显示名称变化不修改历史引用。

### 5.3 预设目录

首批预设：

| 预设 | 协议 | 默认主机 | 可编辑名称 | 可编辑主机 |
| --- | --- | --- | --- | --- |
| HepAI | OpenAI Compatible + OIDC | 构建配置 | 否 | 否 |
| OpenAI | OpenAI Compatible | `https://api.openai.com/v1` | 否 | 否 |
| Anthropic | Anthropic | `https://api.anthropic.com` | 否 | 否 |
| DeepSeek | OpenAI Compatible | `https://api.deepseek.com` | 否 | 否 |
| Ollama | OpenAI Compatible | `http://127.0.0.1:11434/v1` | 否 | 是 |
| 自定义 | 用户选择 | 用户填写 | 是 | 是 |

预设仅是创建草稿的模板，不包含 API Key。预设目录需要版本化，但不得在应用升级时覆盖用户已编辑的实例。

### 6.3 逐步移除或退役

| 旧模块/行为 | 处理方式 |
| --- | --- |
| SharedPreferences 中的提供方 JSON 元数据 | 只用于一次迁移；迁移稳定后删除读写入口 |
| `providerId/modelId` 拼接模型身份 | 迁移为稳定模型 UUID；仅保留兼容读取窗口 |
| ProfileSheet 中的模型切换入口 | 设置页稳定后移除，避免双入口状态不一致 |
| UI 直接拼接 `/chat/completions` 的业务判断 | 移入 wire adapter/endpoint resolver |
| 获取模型后整体替换草稿 | 改为安全合并或显式“同步并查看变化” |
| 仅靠页面底部文本反馈保存结果 | 改为顶部状态区和全局 Snackbar |

## 7. 具体功能点、测试与验收

### F01 设置入口与响应式分组

**功能**

- 左侧栏底部个人信息右侧显示设置按钮。
- 平板宽屏显示分组侧栏和详情双栏。
- 手机窄屏显示分组列表并进入下一级页面。
- 智能体分组包含默认配置和模型设置。

**自动化测试**

- Compose 测试通过 `open-settings` testTag 点击进入。
- 分别使用手机与平板尺寸验证分组文本、选中状态和返回行为。
- `AppRouteTest` 验证 `Settings`、`ModelSettings` path 往返。

**验收**

- 竖屏手机、横屏手机、平板横竖屏均无内容截断。
- 系统字体 1.0、1.3、1.5 倍下导航仍可操作。
- 返回键不会退出登录或丢失无关页面状态。

### F02 预设与自定义提供方创建

**功能**

- 点击添加先选择预设。
- 预设自动填入名称、主机、协议和建议模型。
- 自定义提供方允许编辑名称、主机和协议。
- 新实例使用 UUID；名称不参与身份计算。

**自动化测试**

- 单元测试校验预设集合、默认地址和可编辑规则。
- Repository 测试连续创建同名自定义提供方，ID 必须不同。
- 输入空名称、非法 URL、URL 内嵌凭据、换行地址必须失败。

**验收**

- 所有预设均可进入编辑页。
- 自定义名称可以修改，预设名称按规则锁定。
- 重命名后模型、默认选择和历史引用不变化。

### F03 API Key 安全保存

**功能**

- API Key 写入 Android Keystore 支持的加密存储。
- Room 只保存非敏感元数据。
- 编辑已有提供方时显示“已安全保存”，输入框留空表示不修改。
- 支持替换和随提供方删除凭据。

**自动化测试**

- Repository 测试保存后 Room 表不包含密钥正文。
- 密钥更新失败时元数据不得切换到新 revision。
- 删除提供方后凭据别名不可再读取。
- 日志红action测试覆盖 `Authorization`、`x-api-key` 和常见密钥前缀。

**验收**

- 重启应用后提供方显示“密钥已配置”。
- UI、adb logcat、数据库导出和诊断包中均找不到明文密钥。
- 留空保存不会清除原有密钥。

### F04 一个提供方配置 N 个模型

**功能**

- 手动新建任意数量模型。
- 模型具有真实 ID、显示名称、能力、Token 限制和启用状态。
- 提供方列表点击整行展开/收起并显示总数、启用数。

**自动化测试**

- Repository 分别保存 1、100、500 个模型并验证顺序和唯一约束。
- 重复 upstream ID、空模型 ID 必须返回可理解错误。
- 展开/收起 Compose 测试验证模型只在展开时显示。

**验收**

- 500 个模型时滚动流畅，无明显主线程卡顿。
- 重启后数量、顺序、名称和能力保持一致。
- 提供方重命名不改变任何模型 ID。

### F05 模型发现、合并与同步

**功能**

- “获取”通过草稿地址、协议和密钥请求模型目录。
- 获取结果与现有草稿按 upstream ID 合并。
- 手工模型不会被静默删除。
- 后续增加“同步”模式，先显示新增、保留和缺失模型摘要。

**自动化测试**

- MockWebServer 覆盖 OpenAI `/models` 和 Anthropic `/v1/models`。
- 覆盖 401、403、404、429、超时、空响应、无效 JSON 和 500。
- 合并测试覆盖大小写、重复项、手工模型和能力字段保留。

**验收**

- 获取期间显示进度，按钮防重复点击。
- 失败不改变当前草稿。
- 获取 500 个模型后可以继续搜索、批量操作和保存。

### F06 模型批量管理

**功能**

- 支持清空草稿、全部启用、全部停用。
- 清空需要二次确认，并明确“尚未保存”。
- 后续支持搜索、筛选、多选删除和撤销上一次批量操作。

**自动化测试**

- Compose 测试验证清空确认、取消和确认路径。
- 全部启用/停用后逐项状态一致。
- 批量操作不自动写数据库，返回放弃后正式配置不变。

**验收**

- 对 500 个模型的批量操作在 300 ms 内更新 UI。
- 清空后必须至少新增并启用一个有效模型才能保存。
- 错误原因固定显示在顶部。

### F07 逐模型启用、停用和能力配置

**功能**

- 每个模型可以独立启用或停用。
- 可编辑视觉、工具调用、推理能力、上下文和最大输出。
- 停用模型保留在配置列表，但不进入运行时模型列表。

**自动化测试**

- Room 真机测试保存启用和停用模型并重新读取。
- ViewModel 测试验证运行时列表只包含启用模型。
- 停用当前默认模型后必须选择可用回退模型。

**验收**

- 停用状态重启后保留。
- 停用模型不能在聊天模型选择器中被选中。
- 已停用模型可以重新编辑并启用。

### F08 保存、冲突与反馈

**功能**

- 保存按钮始终可触发校验。
- 保存中显示按钮加载状态和顶部进度条。
- 成功和失败信息固定显示在顶部，长列表无需滚到底部。
- 使用 revision 防止旧草稿覆盖新配置。
- 保存成功后刷新 Repository 快照和运行时模型列表。

**自动化测试**

- 保存成功、校验失败、凭据失败、Room 失败和 revision 冲突测试。
- 连续双击保存只能产生一次有效事务。
- 旋转屏幕或进程恢复时不得重复提交。

**验收**

- 点击保存后 100 ms 内出现可见反馈。
- 失败保留草稿，用户可以修正后重试。
- 成功后列表显示新配置，重启后仍存在。

### F09 默认模型与历史会话

**功能**

- 默认模型保存稳定模型 ID。
- 新会话使用当前默认模型。
- 已有会话保留创建时的模型绑定。
- 删除或停用默认模型时自动回退并提示用户。

**自动化测试**

- 默认模型保存、重启恢复、删除回退和停用回退测试。
- 提供方重命名、模型显示名称修改后历史会话仍可解析。
- 旧拼接模型 ID 迁移测试。

**验收**

- 修改默认模型后创建的新会话立即使用新模型。
- 原有会话不被批量改写。
- 无可用模型时禁止发送并给出设置入口。

### F10 运行时协议路由

**功能**

- 稳定模型 ID 解析为 provider、upstream ID、wire API 和凭据。
- HepAI 使用 OIDC；OpenAI Compatible 使用 Bearer；Anthropic 使用 `x-api-key`。
- 支持文本、图片、工具定义、工具调用增量和完成事件。

**自动化测试**

- MockWebServer 验证 URL、Header、请求体、模型 ID 和工具 schema。
- OpenAI 与 Anthropic SSE 分片、跨 chunk JSON、异常终止和 `[DONE]`/`message_stop` 测试。
- 验证工具名称编码与解码、图片 data URL 转换。
- 验证响应错误不会泄露密钥或原始敏感正文。

**验收**

- 每个预设至少使用一个真实模型完成一次流式文本调用。
- 支持工具的模型完成一次工具调用闭环。
- 取消请求后网络连接和流读取均停止。

### F11 数据迁移与回滚

**功能**

- Room 13→14 创建提供方和模型表。
- 首次加载将旧 SharedPreferences 提供方元数据迁移到 Room。
- 旧密钥引用保持可用；迁移完成前不删除旧数据。
- 回滚版本不能错误解释新表或清除登录数据。

**自动化测试**

- MigrationTestHelper 从 v13 fixture 升级并校验 schema。
- 旧 JSON 中单提供方、多提供方、空模型、损坏 JSON 和缺失密钥测试。
- 重复启动迁移必须幂等。

**验收**

- 已安装旧调试版的真机覆盖安装后正常启动。
- 原默认模型、API Key 和自定义提供方仍可使用。
- 升级失败不导致主数据库整体 destructive migration。

### F12 删除与恢复

**功能**

- HepAI 内置提供方不可删除。
- 删除自定义提供方前显示模型数量、默认模型影响和凭据处理方式。
- 删除事务同时处理模型、默认回退和凭据。
- 后续可增加软删除和短期撤销。

**自动化测试**

- 外键级联删除模型。
- 默认提供方删除时回退到 HepAI 或下一个可用模型。
- 删除凭据失败时返回明确状态，不伪装成功。

**验收**

- 删除后配置列表和聊天模型列表立即同步。
- 重启后删除状态不反弹。
- 日志仅记录提供方 ID，不记录密钥。

## 8. 易用性后续改进清单

按优先级实施：

### P0：发布前必须完成

- 独立“连接检查”，不修改模型草稿。
- API Key 显示/隐藏和“已安全保存”状态。
- 未保存离开确认。
- 模型搜索及已启用/已停用筛选。
- 保存失败原因映射为可行动中文提示。
- 默认模型删除/停用前的影响提示。

### P1：建议同版本完成

- 模型变化摘要：新增、保留、服务端缺失。
- 多选模式、批量删除和撤销。
- 模型能力自动识别并标记信息来源。
- 连接检查与真实模型调用分离，后者明确费用风险。
- 提供方列表显示连接状态、最后检查时间和启用模型数。

### P2：后续增强

- 提供方排序、模型排序和收藏。
- 配置导入/导出，但默认不包含密钥。
- 工作区级默认模型覆盖。
- 配置审计记录和问题诊断导出。
- 与 Windows 共享非敏感 Provider/Model schema。

## 10. 真机关键旅程

1. 从旧版覆盖安装新版，确认登录与会话保留。
2. 进入设置 → 智能体 → 默认配置 → 模型设置。
3. 选择 OpenAI 预设，填写密钥，获取模型，停用部分模型并保存。
4. 杀死进程并重新启动，确认提供方、模型和启用状态恢复。
5. 选择一个启用模型作为默认模型，创建新会话并完成流式回复。
6. 重命名一个自定义提供方，确认默认模型和会话仍正常。
7. 获取 500 个模型，测试搜索、全部停用、清空确认和取消。
8. 制造错误密钥、错误主机、超时和 429，确认顶部反馈准确且草稿保留。
9. 删除非默认提供方，确认模型和凭据被清理。
10. 删除或停用默认模型，确认回退策略和提示。

## 11. 发布门禁

以下条件全部满足才允许发布：

- 所有 P0 功能完成；
- 单元测试、Repository 测试、网络契约测试和 Compose 测试全部通过；
- v13→v14 真机升级通过，且无 destructive migration；
- 至少一个 OpenAI Compatible 和一个 Anthropic 提供方完成真实流式调用；
- API Key 未出现在 Room、日志、诊断包或截图状态中；
- 500 模型场景下无 ANR，批量操作和保存可完成；
- 默认模型停用、删除和提供方重命名均不产生悬空引用；
- 产品、Android、Runtime 和安全负责人完成 Go/No-Go 签字。

## 12. 完成定义

模型配置功能只有在以下条件同时成立时才算完成：

1. 用户能发现、理解并完成配置流程；
2. 保存具有明确反馈且重启后仍存在；
3. 密钥得到独立安全保护；
4. 提供方与模型使用稳定身份；
5. 启用状态真实控制运行时可见性；
6. OpenAI Compatible、Anthropic 和 HepAI 路由均经过契约测试；
7. 旧版本数据可升级，失败可诊断；
8. 每个功能点都有自动化测试和真机验收证据。
