# 远程智能体（官方平台智能体）输出优化方案（修正版）

> **重要修正**：上一版判断「平台远端只发纯文本」是**错误**的。
> 经核实 `cores/python/.../skills_agent/drsai_assistant.py`、`modules/agents/drsai_worker_agent.py`（`HepAIWorkerAgent`）与 `core/src/drsai/dr_sai.py`，远程智能体发出的**事件与消息格式与本地完全一致**（同一套 `DrSaiMessageFactory` 消息词汇 + `type` 字段）。
> 真正的问题是：**Desktop 平台分支把一个"富事件流"当成 OpenAI 兼容文本流来消费**，从而丢掉了全部结构化语义。
> 优化方向因此从"发明新协议"改为"**复用本地同款事件翻译与 runtime 管线**"。

---

## 一、事实校正：两端格式本来就是一致的

### 1.1 本地智能体（Desktop 直连 Runtime/Gateway）

`dr_sai.py` 提供**两个**流式端点：

| 端点 | 函数 | 输出的帧 |
|---|---|---|
| 富事件端点（WebUI 用） | `a_drsai_ui_completions` | `data: {"type":"ModelClientStreamingChunkEvent"\|"AgentLogEvent"\|"TaskEvent"\|"TaskResult"\|..., ...}`（**type 标签的原始消息**） |
| OpenAI 兼容端点 | `chat_completions` | `data: {"choices":[{"delta":{"content":...}}]}`（**只保留 content，其余事件类型丢弃**） |

关键代码（`dr_sai.py: a_drsai_ui_completions`）：

```python
message = await _anext_with_optional_timeout(res, inactivity_timeout_s)
if hasattr(message, "metadata"):
    if message.metadata.get("internal", "no") == "no":
        if isinstance(message, ModelClientStreamingChunkEvent):
            role_tmp = message.source
            if role != role_tmp:
                role = role_tmp
                message.metadata["start_flag"] = "yes"
        message_str = json.dumps(message.model_dump(mode="json"))
        yield f"data: {message_str}\n\n"          # ← 原样输出 type 标签消息
```

### 1.2 远程智能体（HepAIWorkerAgent 消费的 worker 流）

`drsai_worker_agent.py: on_messages_stream` 消费 `a_chat_completions` 返回的流：

```python
stream: Stream = self._funcs_map['a_chat_completions'](**completion_kwargs)
...
async for chunk in self.async_stream_generator(stream, timeout=self._stream_timeout):
    message_type = chunk.get("type", None)                       # ← 同样按 type 分派
    if message_type in self._message_factory._message_types:     # ← 与本地同一张消息注册表
        msg = self._message_factory._message_types[message_type].model_validate(chunk)
        yield msg
    if "stop_reason" in chunk:                                   # ← 同样的终止语义
        break
```

且它导入的消息类与本地一致：

```python
from drsai.modules.managers.messages.agent_messages import (
    AgentLogEvent, Send_level, TaskEvent, DrSaiMessageFactory
)
```

`drsai_assistant.py` 同样 import `ModelClientStreamingChunkEvent / ThoughtEvent / AgentLogEvent`。

**结论**：远程 worker 流 = `{"type": "ModelClientStreamingChunkEvent"|"ThoughtEvent"|"AgentLogEvent"|"TaskEvent"|"ToolCallRequestEvent"|"TextMessage", ...}` + `stop_reason` 终止。
这与本地 `a_drsai_ui_completions` 的帧**同构**。用户判断正确。

### 1.3 差异的真正位置（Desktop 侧）

```
本地智能体: chat.ts ── runRuntimeBackendChat ──► OAEP Session/Run ──►
            projectOaepEventForPresentation ──► type:"structured" ──► 富渲染 ✅

平台智能体: chat.ts ── getPlatformAgentChatUrl() = baseUrl + "/chat/completions"
                     └─ send() fetch ──► readSse()
                          └─ parseChatSseFrame (= parseCompletionSseFrame)
                               只读 choices[0].delta.content ──► type:"chunk" ──► 纯文本 ❌
```

即：**远端发的是富事件，Desktop 却只用一个"读 OpenAI delta"的解析器去读它**，`type` 字段被完全忽略。

## 二、优化方案（对齐本地：复用同一套事件翻译 + runtime）

核心思想：**不再为平台智能体维护一条独立的纯文本旁路**；而是把它接回与本地相同的「事件 → 结构化投影 → 渲染」管线，只是把"OAEP 事件源"换成"远程 worker 事件源"。

### 方案总览

```
                    ┌─────────────────────────────────────────────┐
 本地 Runtime ──► OAEP events ──► projectOaepEventForPresentation ─┐
                                                                  ├─► type:"structured"
 远程 Worker  ──► worker stream ──► projectRemoteEventForPresentation ┘        │
                       (type 标签消息)                                        ▼
                                                                    StructuredMessageParts 富渲染
```

### 2.1 传输层：把平台分支的解析器从"OpenAI delta"换成"type 标签事件"

**文件**：`apps/desktop/shared/main/sseParser.ts` + `chat.ts: readSse`

新增一个与 `parseStructuredConversationSseFrame` 并列的解析器族：

```ts
// sseParser.ts（新增）
export function parseRemoteAgentFrame(frame: string): RemoteAgentFrame | null {
  const payload = getSseData(frame);
  if (!payload || payload === "[DONE]") return null;
  let parsed: unknown;
  try { parsed = JSON.parse(payload); } catch { return null; }
  const record = parsed as Record<string, unknown>;
  const type = typeof record.type === "string" ? record.type : "";
  if (!REMOTE_MESSAGE_TYPES.has(type)) return null;   // 与 DrSaiMessageFactory 注册表对齐
  return { type, raw: record };
}
```

其中 `REMOTE_MESSAGE_TYPES` 直接对齐 `DrSaiMessageFactory._message_types`：

```
ModelClientStreamingChunkEvent, ThoughtEvent, AgentLogEvent,
TaskEvent, ToolCallRequestEvent, TextMessage, FilesEvent,
ToolLongTaskEvent, BackgroundTaskEvent, ModelClientStreamingChunkEvent(结束)
```

在 `readSse` 的帧分派链**最前面**插入 `parseRemoteAgentFrame`，优先于 `parseChatSseFrame`：

```ts
for (const frame of frames) {
  if (isCompletionDoneFrame(frame)) sawDone = true;

  const remoteFrame = parseRemoteAgentFrame(frame);       // ← 新增：优先识别 type 标签事件
  if (remoteFrame) { emitRemoteAgentEvent(webContents, requestId, sessionId, runId, remoteFrame, projection); continue; }

  const structuredEvent = parseStructuredConversationSseFrame(frame);
  // ...原有分支不变...
}
```

> 注意：`parseChatSseFrame`（OpenAI delta）保留为**兜底**，用于远端降级或第三方兼容端点；RSOC/type 标签帧优先。

### 2.2 事件翻译层：新增 `remotePresentationProjector`（与 OAEP projector 同构）

**文件（新增）**：`apps/desktop/shared/main/remotePresentationProjector.ts`

把远程 worker 消息映射为**与本地完全相同的 `StructuredConversationEvent`**，复用 `structuredConversation.ts` 类型：

| 远程 `type` | 映射为 Structured 事件 |
|---|---|
| `ModelClientStreamingChunkEvent`（`metadata.start_flag`） | `turn.started` + `part.started(markdown)` + `part.delta(markdown.append)` |
| `ThoughtEvent` | `part.started(reasoning)` + `part.delta(reasoning.append)` |
| `AgentLogEvent`（`title`/`content`/`send_level`） | `part.started(notice)` / `part.delta(notice.update)` 或 activity |
| `TaskEvent` | `part.started(subtask)` / `progress.update` |
| `ToolCallRequestEvent` / `ToolLongTaskEvent` | `activity.updated(kind:"tool")` |
| `FilesEvent` | `activity.updated(kind:"file_change")` → 渲染为 artifact/file 卡片 |
| `TextMessage`（final） | `part.completed(markdown, final:true)` |
| `TaskResult` / `stop_reason` | `turn.completed`（`meta.backend="platform:"+platformId`, `durationMs`） |

```ts
export function createRemotePresentationProjection(turnId: string, backend: string) { ... }
export function projectRemoteEventForPresentation(
  frame: RemoteAgentFrame,
  projection: RemotePresentationProjection,
): StructuredConversationEvent[] { ... }   // 产出与 OAEP 版同形的 type:"structured"
```

关键：**产出的事件类型与 `projectOaepEventForPresentation` 完全一致**（`turn.started` / `part.started` / `part.delta` / `part.completed` / `activity.updated` / `turn.completed`），这样**渲染层零改动**。

### 2.3 渲染层：adapter 统一入口（几乎不动）

- `useDesktopChatAdapter` 已经按 `type:"structured"` 处理 → 平台 run 只要产 `structured` 事件，即自动获得 `structuredTurn` 与 `StructuredMessageParts` 富渲染。
- 唯一增量：平台 turn 的 `meta.backend` 前缀识别，在 `formatBackendLabel` 中把 `platform:` 显示为「远程/平台」徽标，并复用 `AgentSquareView` 已有的隐私提示文案。

### 2.4 Runtime 归属：与本地一致地建立 Session/Run 语义

用户指出应"与本地一样走 runtime"。建议：

1. **优先方案（完全对齐）**：平台智能体也通过 Runtime 的 Agent Backend 机制接入——在 Runtime 侧注册一个 `platform_worker@1` backend（内部即 `HepAIWorkerAgent`,参考 `task_team.py:537`），Desktop 走与本地相同的 `subscribeOaepSession`/`createAgentRun` 路径。此时**平台事件天然进入 OAEP 投影**，Desktop 侧几乎不需要新代码，只需让 backend 把 worker 的 `type` 标签 chunk 转成 OAEP `event.item.*`。
2. **过渡方案（改动最小）**：保持 `getPlatformAgentChatUrl()` 直连 DDF，但在 `readSse` 里接入 §2.1/§2.2 的 `remotePresentationProjector`，把 worker 事件在 Desktop 侧翻译为 `structured` 事件。终态补齐 `turn.completed`。

> 建议：**先做过渡方案拿到渲染对齐（1～2 天级）**，再逐步迁移到方案 1（Runtime backend），最终让两条链路在协议与 runtime 上彻底统一。

### 2.5 其它配套修正

1. **能力通告**：`hostedAgentCatalog.ts` 移除 `capabilities: ["chat","streaming"]` 硬编码，改读远端真实能力（含 `structured`/`tools`/`files`）；`isPlatformAgentExecutionAvailable` 据此放开。
2. **Token 语义**：`resolvePlatformBearerToken` 按 `authMode` 显式分流（OIDC 优先，API-key 兜底可审计），避免把 API key 当 OIDC token 静默发给远端（详见上一轮分析）。
3. **附件**：平台侧也走 `stageAttachments` 生成 `OaepInputResource`，与本地一致地渲染资源卡片。
4. **终止与恢复**：`stop_reason` → `turn.completed`；断线续传沿用 `resumeState` + `Idempotency-Key`；worker 终态保证幂等（对照 `_needs_auto_continue_retry` 的空内容重试语义）。

## 三、落地顺序与验收

| 阶段 | 内容 | 收益 |
|---|---|---|
| P0 | `readSse` 接入 `parseRemoteAgentFrame` + `remotePresentationProjector`（过渡方案） | 平台渲染立即对齐本地富渲染 |
| P0 | 平台 `stop_reason` → `turn.completed`（含 meta） | 终态展示一致 |
| P1 | `hostedAgentCatalog` 能力真实通告 + `resolvePlatformBearerToken` 按 authMode 分流 | 可判定、可审计 |
| P1 | 附件走 `stageAttachments` | 资源卡片一致 |
| P2 | Runtime 侧注册 `platform_worker@1` backend，走统一 OAEP 路径 | 协议/runtime 彻底收敛 |

**验收标准**
- 平台 run 产出 `type:"structured"` 事件，渲染出 markdown/reasoning/notice/subtask/tool/file/artifact，与本地**同构**。
- 平台 run 具备 `meta.backend`、`durationMs`。
- 远端降级为纯 OpenAI delta 时，自动回落现有 `chunk` 纯文本路径（回归无劣化）。
- 未知 `type` 帧被计数遥测、不崩溃。

## 五、一句话总结

远程智能体发出的就是**与本地同款的 `type` 标签事件流**（`ModelClientStreamingChunkEvent`/`ThoughtEvent`/`AgentLogEvent`/`TaskEvent`/`ToolCallRequestEvent` + `stop_reason`）。渲染之所以不同，是因为 Desktop 平台分支调的是 OpenAI 兼容端点、并用"只读 `choices.delta.content`"的 `readSse` 去消费它，把所有结构化语义压成了纯文本。优化方案：在 `readSse` 优先识别 `type` 标签帧，用一个与 `oaepPresentationProjector` 同构的 `remotePresentationProjector` 把它们翻译成与本地相同的 `structured` 事件，从而让渲染层零改用地复用富组件；中长期则把远程智能体注册为 Runtime 的一个 backend，与本地彻底走同一条 OAEP + runtime 管线。
