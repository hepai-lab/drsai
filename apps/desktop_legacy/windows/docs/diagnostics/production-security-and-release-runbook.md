# 生产诊断安全与发布运行手册

## 安全边界

- 默认只采集最少运行元数据；源码、远程目标、交互调试和导出均受独立授权控制。
- 诊断包导出前执行字段分类、内容最小化和二次敏感信息扫描，默认使用 AES-256-GCM 加密，并以 SHA-256 校验明文完整性。
- 远程传输默认关闭；开启后也只能传输已完成相同扫描和加密的诊断包。表达式求值只读，远程调试端点只接受本机 SSH 隧道。
- 主要威胁包括令牌泄露、路径越权、恶意诊断包、调试附加滥用、资源耗尽和诊断系统阻塞主业务。对应控制为脱敏、授权、格式/完整性校验、只读求值、预算背压和失败降级。

## 泄露与故障响应

1. 设置 `OPENDRSAI_DIAGNOSTICS_EMERGENCY_DISABLE=1` 紧急关闭采集与调试入口。
2. 隔离相关诊断包和损坏文件，撤销可能暴露的凭据，保留不含敏感值的审计记录。
3. 由安全负责人判定影响范围，研发修复规则或协议，客服向用户反馈处置状态。
4. 使用人工敏感样本、越权路径、篡改包和回归套件复验后再逐步恢复灰度。

## 发布与兼容门禁

- Owner：Desktop Runtime 负责采集与恢复；Security 负责隐私和威胁模型；Support 负责诊断包交接；Release 负责安装、升级、回滚及紧急关闭演练。
- 每次发布运行 `npm run verify:production-diagnostics`、诊断全量回归、生产构建和安装包冒烟；阻断级安全问题、数据损坏或主流程阻塞必须清零。
- 包格式带版本、最低读取器和兼容声明。当前读取 v1，并接受 v0 明文包迁移；未知版本拒绝导入且不修改用户数据。
- 灰度使用 `OPENDRSAI_DIAGNOSTICS_ROLLOUT_PERCENT`；指标异常时先自动降采样，再使用紧急关闭开关。回滚版本必须仍能读取受支持的旧包和旧事件。

## 标准支持交接

用户先预览诊断包范围，再授权导出；客服完成初筛并记录复现步骤；研发离线验证完整性、查看环境/会话/根因证据；修复后把结论和规避方案反馈用户。未经用户授权不启用远程传输。
