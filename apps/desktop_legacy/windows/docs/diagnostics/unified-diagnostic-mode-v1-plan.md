# OpenDrSai 统一诊断模式 V1 开发方案

状态：已完成（2026-07-18）  
范围：第一阶段诊断模式，不包含断点、单步执行、变量查看和变量修改。

## 目标

为 OpenDrSai Desktop 的所有模块提供统一诊断反馈，回答四个问题：

1. 当前运行到哪里；
2. 正在等待哪个模块；
3. 哪个模块失败；
4. 错误对应哪个源文件、函数和代码位置。

Codex Adapter 是首个完整验证对象，但诊断协议、采集、存储、健康状态和 F12 界面均属于 OpenDrSai 平台层。OpenDrSai Backend、Workspace、SSH、终端、浏览器及后续 Backend 使用同一套能力。

## 交付范围：7 个模块、28 个功能点

### D1 统一诊断协议

- [x] F01 定义开始、进行中、等待、完成、失败和取消事件。
- [x] F02 统一 trace、span、parent span、session、turn、run 和 operation 标识。
- [x] F03 表达跨模块父子调用关系和时间信息。
- [x] F04 统一模块、组件、等级、错误与源代码位置口径。

### D2 诊断接入层

- [x] F05 接入 Renderer 用户操作、控制台和未处理异常。
- [x] F06 接入 Electron Main、Preload 和 IPC 调用。
- [x] F07 接入 Gateway、Runtime Engine 和结构化运行事件。
- [x] F08 接入 OpenDrSai/Codex Backend、Workspace、SSH、终端和工具模块。

### D3 事件采集与链路聚合

- [x] F09 聚合不同进程和 Runtime 的诊断事件。
- [x] F10 按 trace 生成端到端执行链路与调用树。
- [x] F11 处理事件乱序、重复和延迟到达。
- [x] F12 支持断开暂存、恢复补齐与状态收敛。

### D4 诊断记录与生命周期

- [x] F13 保存近期记录并支持应用重启后查看。
- [x] F14 限制内存、记录数量、单条大小和磁盘占用。
- [x] F15 支持按 trace、模块、状态、等级和时间查询。
- [x] F16 导出经过脱敏的诊断包。

### D5 异常与代码定位

- [x] F17 捕获 Renderer、Electron、Node.js 和 Python 未处理异常。
- [x] F18 统一整理不同语言和进程的调用堆栈。
- [x] F19 将可用堆栈定位到源文件、函数、行和列。
- [x] F20 对超时、无响应和进程退出生成诊断快照。

### D6 进程与连接健康

- [x] F21 登记 Renderer、Electron Main、Gateway、Backend、Codex 和远程连接。
- [x] F22 显示运行、等待、断开、重启、降级和失败状态。
- [x] F23 记录退出、自动重启、连接重试和最后心跳。
- [x] F24 根据事件和健康状态给出初步故障判断。

### D7 F12 诊断中心

- [x] F25 提供全局运行概览和当前活动列表。
- [x] F26 提供执行时间线和模块调用树。
- [x] F27 提供异常堆栈、源代码位置和相邻事件查看。
- [x] F28 支持筛选、搜索、暂停、复制、清空和诊断包导出。

## 实施轮次

1. 统一基础：D1、D3、D4；
2. 主要路径接入：D2；
3. 错误和健康诊断：D5、D6；
4. F12 诊断中心：D7；
5. 全量测试、故障注入、安全、性能和发布验收。

## 测试方案

### 单元测试

覆盖事件校验、标识生成、状态转换、父子关系、排序、去重、脱敏、堆栈解析、容量限制和过期清理。

### 集成测试

覆盖 Renderer → Preload → Electron Main → Gateway → Runtime → Backend 的链路，以及 Workspace、SSH、终端和工具边界。

### 故障注入

覆盖 Gateway 未启动、Backend 不可用、Codex 退出、IPC 异常、网络超时、SSH 断开、Python 异常、Renderer 异常、事件乱序重复和执行中重启。

### 界面验收

验证 F12 可找到当前运行位置、展开调用树、定位首个失败节点、查看堆栈和源代码位置、返回对应会话、筛选模块并导出诊断包。

### 安全与性能

验证不记录令牌、密码、Cookie 和完整认证信息；默认不保存完整消息、命令输出和文件正文；诊断记录有界；诊断失败不影响业务；高频事件下界面保持可用。

## 完成标准

- 所有主要操作拥有唯一 trace，并能跨进程组成调用树；
- 所有主要组件使用同一协议，不存在 Codex 专用诊断格式；
- 异常能关联模块、堆栈和可用的源代码位置；
- 进程退出、断线、等待和超时可识别；
- 本地与远程 Runtime 使用相同结构；
- F12 完成查看、筛选、定位、清空和导出；
- 诊断数据脱敏、有界，且诊断系统故障不影响 OpenDrSai 主功能。

## 实施与验收结果

- 7 个模块、28 个功能点均已完成。
- 统一诊断专项验证通过：协议、链路聚合、乱序去重、状态收敛、持久化、脱敏、健康状态、堆栈定位、IPC 与界面契约。
- F12 视觉验收通过：概览、调用树、错误源码位置、搜索筛选及横向溢出检查。
- Electron 主进程、Preload、Renderer 类型检查通过，生产构建及 source map 生成通过。
- Python Runtime/Backend 相关测试 33 项通过，另含 12 项子测试；异常诊断不会泄露用户目录或测试注入的敏感信息。
- 桌面端其余回归验证均通过，包括结构化会话、Gateway、SSE、认证、Workspace、启动性能与 UI 验收。
- 最终统一回归入口在 2026-07-18 复跑时，被并行开发的语音模块 `voiceMessageText.ts` 导入后缀类型错误中止；诊断专项与结构化调试复验通过，该错误不在本方案改动范围内。
