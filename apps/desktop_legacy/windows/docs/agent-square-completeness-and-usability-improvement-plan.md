# Windows 智能体广场功能完整性与易用性改造方案

## 1. 目标

本方案在现有“本机 OpenDrSai + HAI 平台智能体”实现上完成一次收敛，重点解决：

- 首次进入智能体广场等待时间长；
- 浏览目录会意外启动本机 Runtime；
- App 初始化与广场重复请求 HAI；
- 平台缓存和选择状态可能跨账号残留；
- 卡片可见、可用状态和真实执行能力不一致；
- “设为默认”“最近使用”“运行模式”等未闭环或面向实现的功能干扰用户；
- 当前测试偏重源码字符串，未验证时序、账号隔离和真实 App 调用链。

## 2. 产品边界

智能体广场只承担四件事：发现、理解、选择和使用智能体。

- 本机区域只展示 `OpenDrSai`；稳定 ID 继续为 `my-drsai`。
- 非本机智能体只从 HAI `/apiv2` 目录读取。
- Codex 是本机执行后端，不作为普通广场智能体展示；其入口保留在聊天后端选择器和相关设置中。
- OpenDrSai 的详细配置和记忆管理移出广场正文，使用独立对话框或设置入口。
- 卡片不展示 `ddf`、`remote`、URL 等实现细节，只展示名称、作者、描述、可用性和用户可理解的能力。

## 3. 目标加载模型

```text
进入智能体广场
  ├─ 立即构造本机 OpenDrSai 卡片（不得启动 Runtime）
  ├─ 读取当前 OIDC sub 对应的内存/磁盘缓存
  ├─ 先显示本机和缓存结果
  └─ 后台刷新 HAI
       ├─ 同一平台、同一用户只允许一个请求在途
       ├─ 成功后原子替换目录和状态
       └─ 失败时保留缓存并明确标记
```

性能目标：

- 本机卡片和已有缓存应在 200ms 内可见；
- `listAgents()` 不得启动 Gateway、Python Runtime 或 Codex；
- 普通进入页面复用短期内存缓存；
- 手动刷新才发送 `refresh=true`；
- 可选 Native 元数据不得阻塞 HAI `/apiv2` 目录首屏；
- 同一账号的并发目录请求合并为一次。

## 4. 开发项

### A. 加载性能与状态一致性（6 项）

1. 本机目录读取改为无副作用快照，不启动 Runtime。
2. 移除广场对 Codex 账号和模型目录的主动探测。
3. 增加平台目录内存 TTL 和 single-flight。
4. 增加 cache-first、background-refresh 加载方式。
5. 将 agents 与 platform status 通过单一快照 IPC 返回。
6. 从首屏关键路径移除 Portal Native 元数据请求。

### B. 身份与缓存隔离（4 项）

1. 磁盘缓存按平台环境和 OIDC `sub` 的哈希隔离。
2. 内存目录、执行描述符和在途请求按 `sub` 隔离。
3. 登录主体变化时重新加载目录并清理无效选择。
4. 缓存目录只表示“曾经发现”，不得伪装成当前运行状态。

### C. 平台执行契约（5 项）

1. 平台对话准入由功能开关和所选智能体自身 `chat`/`streaming` 能力决定。
2. 目录可见性、按钮可用性和发送前校验使用同一规则。
3. DDF 取消至少可靠终止本地 SSE；服务端停止仅在有真实协议时调用。
4. DDF input-response 继续走 `/apiv2/agents/input`，Native input 仅用于对应模式。
5. Logo 只允许可信 HTTPS/平台相对地址，不直接加载任意第三方 URL。

### D. 用户界面收敛（7 项）

1. 移除“设为默认”星标和平台默认写入口。
2. 移除未持久化的“最近使用”排序和 usage 写请求。
3. 移除卡片、详情中的运行模式和技术 URL。
4. 平台状态改为“可用/不可用/缓存结果”，不显示“远程·运行中”。
5. 区分首次加载、无搜索结果、无权限、登录过期、缓存降级和网络失败。
6. OpenDrSai 配置改为独立模态界面，关闭后返回广场位置。
7. 详情弹窗补齐 Escape、初始焦点和关闭焦点恢复等基本可访问性。

### E. 测试与发布验收（6 项）

1. 测试目录读取不会启动 Runtime。
2. 测试缓存首屏、后台刷新和并发合并。
3. 测试用户 A/B 缓存和执行描述符隔离。
4. 测试每智能体能力准入、DDF 取消和 input-response 路由。
5. 将默认按钮、运行模式等旧源码断言替换为行为断言。
6. 通过 TypeScript、Python、视觉、源码态/打包态 OIDC E2E 和真实 HAI 联调。

本方案共 **5 类开发项、28 个功能点**。

## 5. 验收标准

- 打开广场时立即看到 OpenDrSai；已有缓存时同时看到上次 HAI 目录。
- 浏览和刷新广场不会启动本机 Runtime。
- 同一账号并发打开/初始化只产生一个 HAI 目录请求。
- 用户 A 的“我的智能体”不会在用户 B 的缓存或选择中出现。
- 卡片显示可用时，点击“开始使用”能够进入并通过同一能力规则发送消息。
- 缓存结果有明确标识，不声称智能体当前正在运行。
- 不再出现默认星标、最近使用排序、raw mode 和技术 URL。
- OpenDrSai 配置不再撑开广场正文。
- DDF 对话、输入响应、取消、401 刷新和错误提示均通过真实或契约级测试。
- Windows 构建、打包应用 E2E 和真实 HAI 目录/对话联调全部通过。

## 6. 实施顺序

1. 先完成 A、B，解决等待时间和账号隔离。
2. 再完成 C，统一“看得见、点得动、发得出”的执行契约。
3. 完成 D 的界面减法和状态表达。
4. 最后完成 E，清理旧断言并执行真实环境和打包验收。

## 7. 实施结果与验收记录

截至 2026-08-04，A～D 和 E1～E5 已完成，共完成 **27/28 个功能点（96%）**：

- 目录首屏改为本机快照与用户级缓存优先，HAI 目录在后台刷新；同一用户的并发请求使用 single-flight 合并。
- 本机目录发现不再启动 Gateway、Python Runtime 或 Codex；OpenDrSai 保持稳定 ID `my-drsai`，实际使用时再按需启动 Runtime。
- 平台内存缓存、磁盘缓存、执行描述符和在途请求均按 OIDC `sub` 隔离；磁盘文件名仅保存哈希，不写入原始用户标识。
- 平台智能体由 HAI `/apiv2` 返回的单智能体 `chat`、`streaming` 能力决定是否可用；目录、按钮和发送前校验共用同一规则。
- DDF 对话保留 `/apiv2` 路由，input-response 可在服务端未给显式请求 ID 时回退到当前请求，取消能够可靠中断本地 SSE，且不误调 Portal Native stop。
- 广场移除了默认星标、最近使用排序、运行模式和技术 URL；缓存结果明确标为不可直接使用；OpenDrSai 配置移入具备焦点管理的模态框。
- 平台 Logo 仅接受受信平台域名的 HTTPS 地址或相对地址；远程 SSH 字符串错误响应也能稳定归一化，不再触发二次 TypeError。

已通过的自动化验收：

- TypeScript 主进程与渲染进程类型检查。
- Windows 主进程、preload、renderer 完整构建。
- 智能体广场 UI、目录、加载时序、平台契约、云端路由、远程错误协议测试。
- 平台认证测试（含 15 项 Python 测试）、三视口视觉测试。
- 源码态和打包态 Electron OIDC 端到端测试。
- `electron-builder --dir` 未打包应用生成与签名。

剩余 E6 的真实 HAI 在线复验需要本机有效的 HepAI OIDC 安全存储会话。当前 `~/.drsai/auth/auth.json` 不存在，因此测试在发起网络请求前按预期终止；重新登录后执行 `npm run verify:live-platform-oidc` 完成最后验收。历史联调曾验证 4 个 HAI 智能体、模型目录和 DDF SSE 对话成功，但该记录不替代本次改造后的在线复验。
