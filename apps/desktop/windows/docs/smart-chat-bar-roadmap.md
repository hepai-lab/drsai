## Current Agent Workflow Slice

Design: enforce the shared execution policy at the privileged IPC boundary, while routing explicit side-effect proposals through the Approval Center when the policy requires confirmation. Agent-proposed shell commands, Files panel workspace stage/revert actions, `/commit <message>` git commits, approval-required workflow run recipes, fork queue-start requests, and fork merge-back/discard lifecycle actions enter Approval Center first and execute only after approval. `/commit` now runs a read-only staged-diff preflight before queuing approval, so empty staged commits are blocked and Approval Center receives the same staged files, grouped file review, diff size, unstaged-change risk, test commitment, and latest terminal test/verification result shown in chat; the Approve action is gated until staged-file scope, unstaged-change risk, and test commitment are locally confirmed. `plan_mode` maps to `read_only`, so the same paths are blocked when the user is planning or the workspace is untrusted. Slash command mode actions are held as first-class chat adapter state, displayed in the composer, sent with the next model request as explicit runtime metadata, and consumed by the legacy Python SSE gateway as whitelisted backend task guidance; `/fork <intent>` additionally asks the main process to prepare an isolated branch-backed Git worktree under the desktop data directory, creates a local `agent_run` fork thread pointing at that worktree, persists source/worktree/branch/base metadata with an active lifecycle state, reports source dirty-state risk, switches the app to it without sharing the source workspace, exposes copyable fork details from the thread menu for lifecycle review, and routes merge-back/discard requests through Approval Center before executing clean-worktree merge-back or desktop-managed worktree cleanup. `/fork queue <task1; task2>` marks each fork thread with queue group/index/status metadata, supports optional `@agent` prefixes per subtask for dispatch assignment, queues `fork.queue_start` approval before the queue can move from waiting to ready, and refreshes thread state to `ready` or `blocked` after the Approval Center decision; `/fork dispatch` is the explicit later step that starts approved ready subtasks as agent runs inside their isolated worktrees and records running/completed/blocked queue states. Merge conflicts and dirty worktrees keep the fork in `merge_pending` with a lifecycle message; successful merge records `merged` and marks branch cleanup pending, and successful cleanup records `closed` plus branch cleanup status. Cleanup removes the controlled worktree, deletes already-merged fork branches with safe `git branch -d`, and archives unmerged discarded branches under `drsai/archive/...` instead of dropping work. Project memory is explicit and workspace-scoped: `/memory add <note>` writes a bounded, validated entry to the main-process desktop data store, `/memory edit <index|id> <note>` updates one entry, `/memory delete <index|id>` removes one entry, `/memory retrospective <note>` captures task lessons, `/memory` lists recent entries before they influence a task, Skills Square provides a visual review/edit/delete surface, skill-promotion candidates can be turned into reviewable desktop-data `SKILL.md` draft files, reviewed drafts can be installed into a safe local desktop skills target, and natural-language sends include recent project memory as a visible system section. Background tasks are a durable status layer rather than a side-effect bypass: workflow runs mirror into a workspace-scoped background task queue, while terminal/chat dispatch still goes through the existing workflow and approval paths. Scheduled monitors persist cadence, target, approval, and verification metadata; their manual due-scan and the main-process real clock/restart worker both start eligible workflow runs through the same approval-gated workflow path and advance `nextRunAt` without bypassing Approval Center. On app restart, persisted in-flight workflow runs are converted into explicit restart resume plans: chat steps can be re-sent, terminal steps can be re-prepared through approval, manual checkpoints can be confirmed, and Approval Center steps remain waiting. Skills Square displays worker status telemetry, restart resume state, and a Resume action for blocked monitor definitions; the remaining scheduler gap is fully autonomous external process reconnect after restart. The Approval Center derives policy rows from the same shared evaluator and consumes a unified pending-approval queue exposed by the main process, seeded by browser-use action proposals, agent shell command proposals, Files panel workspace mutation proposals, git commit proposals, workflow run proposals, fork queue-start proposals, fork lifecycle proposals, and by a generic proposal bridge for future network/connector producers.
