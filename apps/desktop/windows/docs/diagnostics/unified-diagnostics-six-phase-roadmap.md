# OpenDrSai Desktop 统一诊断与调试六阶段开发方案

状态：总体规划完成；第一阶段已实施，第二至第六阶段待开发。  
范围：OpenDrSai Desktop 全模块统一诊断、源码定位、深度追踪、根因分析、交互式调试和生产级交付。  
统计口径：每个模块包含 4 个可独立开发和验收的功能点。

## 总体目标

建立一套面向 OpenDrSai Desktop 所有模块的统一诊断与调试平台，使用户可以逐步完成以下闭环：

1. 看见程序运行过程；
2. 从错误进入对应源码；
3. 深入模块内部和跨机器链路；
4. 自动识别故障根因；
5. 暂停程序并检查运行现场；
6. 在正式发布环境中安全、稳定地使用。

总体路线：`统一诊断 → 源码定位 → 深度追踪 → 根因分析 → 交互式调试 → 生产级平台`。

## 第一阶段：统一诊断模式（Unified Diagnostics）

状态：已完成。  
目标：回答“运行到哪里、正在等待谁、哪个模块失败、错误发生在哪个代码位置”。  
范围：7 个模块、28 个功能点。

### P1-M1 统一诊断协议

- P1-F01 定义开始、进行中、等待、完成、失败和取消事件。
- P1-F02 统一 Trace、Span、Session、Turn、Run 和 Operation 标识。
- P1-F03 表达跨模块父子调用关系与时间信息。
- P1-F04 统一模块、组件、等级、错误和源码位置口径。

### P1-M2 诊断接入层

- P1-F05 接入 Renderer 用户操作、控制台与未处理异常。
- P1-F06 接入 Electron Main、Preload 和 IPC 调用。
- P1-F07 接入 Gateway、Runtime Engine 和结构化运行事件。
- P1-F08 接入 Backend、Codex、Workspace、SSH、终端和工具边界。

### P1-M3 事件采集与链路聚合

- P1-F09 聚合不同进程和 Runtime 的诊断事件。
- P1-F10 按 Trace 生成端到端执行链路与调用树。
- P1-F11 处理事件乱序、重复和延迟到达。
- P1-F12 支持断开暂存、恢复补齐与状态收敛。

### P1-M4 诊断记录与生命周期

- P1-F13 保存近期记录并支持应用重启后查看。
- P1-F14 限制内存、记录数量、单条大小和磁盘占用。
- P1-F15 支持按 Trace、模块、状态、等级和时间查询。
- P1-F16 导出经过脱敏的诊断包。

### P1-M5 异常与代码位置采集

- P1-F17 捕获 Renderer、Electron、Node.js 和 Python 异常。
- P1-F18 统一整理不同语言和进程的调用堆栈。
- P1-F19 提取源文件、函数、行和列位置。
- P1-F20 对超时、无响应和进程退出生成诊断快照。

### P1-M6 进程与连接健康

- P1-F21 登记 Renderer、Main、Gateway、Backend、Codex 和远程连接。
- P1-F22 显示运行、等待、断开、重启、降级和失败状态。
- P1-F23 记录退出、自动重启、连接重试和最后心跳。
- P1-F24 根据事件和健康状态生成初步故障判断。

### P1-M7 F12 诊断中心

- P1-F25 提供全局运行概览和当前活动列表。
- P1-F26 提供执行时间线和模块调用树。
- P1-F27 提供异常堆栈、源码位置和相邻事件查看。
- P1-F28 支持筛选、搜索、暂停、复制、清空和诊断包导出。

### 第一阶段测试与验收

- 单元测试：协议校验、状态转换、排序、去重、聚合、脱敏、容量限制、堆栈解析。
- 集成测试：Renderer → Preload → Main → Gateway → Runtime → Backend 全链路。
- 故障测试：IPC 异常、Gateway 不可用、Codex 退出、SSH 断开、超时、进程无响应。
- 界面测试：概览、调用树、错误位置、筛选、清空、导出和不同窗口尺寸。
- 安全测试：令牌、密码、Cookie、用户目录和消息正文不得进入诊断包。
- 验收门槛：28 个功能点通过；诊断故障不影响业务；专项、视觉和相关回归测试通过。

## 第二阶段：源码定位闭环（Source Navigation）

状态：已完成（2026-07-18）。  
目标：让每条有效错误和堆栈帧都能从诊断中心进入正确的本地或远程源码。  
依赖：第一阶段。  
范围：5 个模块、20 个功能点。

### P2-M1 Source Map 解析

- P2-F01 建立构建产物与 TypeScript 原始源码映射服务。
- P2-F02 支持 Main、Preload、Renderer 和动态分包 Source Map。
- P2-F03 处理缺失、损坏、版本不匹配和内联 Source Map。
- P2-F04 缓存解析结果并控制解析开销。

### P2-M2 统一源码地址

- P2-F05 定义本地、Workspace、安装包、Python 和远程源码统一地址。
- P2-F06 规范 Windows 路径、URI、盘符、大小写和路径分隔符。
- P2-F07 将容器、远程主机和虚拟环境路径映射到 Workspace。
- P2-F08 标记源码可信度、版本、可用性和访问权限。

### P2-M3 源码读取与上下文

- P2-F09 安全读取错误行前后的有限代码上下文。
- P2-F10 支持 TypeScript、JavaScript、Python 和配置文件。
- P2-F11 对大文件、二进制文件、不可访问文件和编码异常降级。
- P2-F12 对源码片段执行敏感信息过滤和访问范围限制。

### P2-M4 编辑器导航

- P2-F13 从堆栈帧一键打开对应文件、行和列。
- P2-F14 支持内置查看器、系统默认编辑器和配置的外部编辑器。
- P2-F15 支持本地 Workspace 与 SSH Workspace 导航。
- P2-F16 记录导航失败原因并提供复制路径等替代操作。

### P2-M5 源码诊断界面

- P2-F17 在 F12 中展示源码片段、高亮错误行和调用函数。
- P2-F18 在原始位置与 Source Map 位置之间切换。
- P2-F19 支持调用栈帧切换和相邻诊断事件联动。
- P2-F20 显示源码版本、映射状态和不可用原因。

### 第二阶段测试与验收

- 单元测试：路径归一化、Source Map 映射、URI 转换、上下文截取、缓存和脱敏。
- 集成测试：开发构建、生产构建、安装包、Python、Workspace 和 SSH 源码导航。
- 故障测试：Source Map 缺失或损坏、源码被移动、远程断线、权限不足、版本不一致。
- 界面测试：点击堆栈、帧切换、源码高亮、原始/映射位置切换和导航降级。
- 安全测试：禁止越过 Workspace 授权范围读取文件；源码上下文不得进入默认导出包。
- 验收门槛：受支持堆栈均能打开正确位置或说明失败原因；生产构建映射准确；导航失败不影响诊断查看。

## 第三阶段：全链路深度追踪（Deep Tracing）

状态：已完成（2026-07-18）。  
目标：从模块边界深入到模块内部关键步骤，并可靠连接本地、远程和重启前后的链路。  
依赖：第一阶段；与第二阶段可部分并行。  
范围：6 个模块、24 个功能点。

### P3-M1 业务级追踪

- P3-F01 为会话、消息、Agent Run 和模型调用建立业务 Span。
- P3-F02 为文件读写、命令执行、工具调用和审批建立子 Span。
- P3-F03 为终端、浏览器、Workspace 和搜索操作建立子 Span。
- P3-F04 统一成功、重试、取消、降级和部分完成语义。

### P3-M2 Runtime 与 Backend 深度追踪

- P3-F05 追踪 Gateway 路由、队列、Runtime 调度和 Backend 执行阶段。
- P3-F06 追踪 Codex Adapter 请求、事件流、工具回合和退出过程。
- P3-F07 记录资源等待、并发限制、背压和超时来源。
- P3-F08 在保持统一协议的前提下支持后续 Backend 接入。

### P3-M3 远程与跨机器链路

- P3-F09 传播跨进程、跨 SSH 和跨 Runtime Trace Context。
- P3-F10 校正跨机器时钟偏差并保留原始时间。
- P3-F11 支持远程事件批量传输、确认和断线暂存。
- P3-F12 处理重连后的补传、去重和父子关系修复。

### P3-M4 生命周期连续性

- P3-F13 持久化活跃 Trace 检查点。
- P3-F14 在 Main、Gateway 或 Runtime 重启后恢复未完成链路。
- P3-F15 识别孤儿 Span、失联进程和永久缺失事件。
- P3-F16 对恢复、放弃和超时收敛给出明确状态。

### P3-M5 性能与资源追踪

- P3-F17 记录关键步骤耗时、排队时间和首事件延迟。
- P3-F18 关联 CPU、内存、事件循环延迟和进程资源快照。
- P3-F19 识别慢调用、重复重试和高成本工具调用。
- P3-F20 提供 Trace、模块和操作级性能统计。

### P3-M6 深度追踪界面

- P3-F21 提供可缩放时间线、瀑布图和关键路径。
- P3-F22 支持按进程、机器、模块和状态折叠调用树。
- P3-F23 展示重试、断线、补传、重启和降级节点。
- P3-F24 支持从性能异常跳转到事件、错误和源码。

### 第三阶段测试与验收

- 单元测试：Trace Context 传播、时钟校正、补传去重、孤儿修复、关键路径计算。
- 集成测试：终端、浏览器、工具、文件、Codex、Gateway、Runtime 和远程 SSH 链路。
- 故障测试：乱序、重复、丢包、断线重连、Main/Gateway/Runtime 重启和跨机时钟漂移。
- 性能测试：高频事件、长 Trace、大调用树、批量传输和渲染压力。
- 界面测试：时间线缩放、折叠、关键路径、跨机器标识和源码联动。
- 验收门槛：主要业务操作无不可解释链路断点；恢复后状态可收敛；诊断开销满足发布预算。

## 第四阶段：智能根因分析（Root Cause Intelligence）

状态：已完成（2026-07-18）。  
目标：从“展示发生了什么”升级到“解释真正为什么失败以及建议如何处理”。  
依赖：第一至第三阶段。  
范围：5 个模块、20 个功能点。

### P4-M1 故障模型与规则引擎

- P4-F01 建立故障类型、严重程度、影响范围和可恢复性模型。
- P4-F02 定义超时、断线、崩溃、认证、配置和资源故障规则。
- P4-F03 支持规则版本、优先级、启停和冲突处理。
- P4-F04 为各模块提供统一、可扩展的诊断规则接口。

### P4-M2 根因与传播分析

- P4-F05 识别执行链中的首个有效失败节点。
- P4-F06 区分根因、传播错误、重试错误、用户取消和噪声。
- P4-F07 根据因果关系、时间和依赖关系计算根因置信度。
- P4-F08 对多个候选根因提供排序和证据说明。

### P4-M3 错误聚类与趋势

- P4-F09 基于错误码、规范化堆栈、模块和上下文生成指纹。
- P4-F10 聚合同类错误并统计次数、影响会话和首次/最近发生时间。
- P4-F11 识别新出现、持续恶化和版本相关故障。
- P4-F12 支持忽略、合并、拆分和标记已知问题。

### P4-M4 修复建议与知识库

- P4-F13 为确定性故障提供规则化检查步骤和修复建议。
- P4-F14 关联配置项、健康状态、源码位置和相关历史事件。
- P4-F15 生成不包含敏感内容的故障摘要和复现线索。
- P4-F16 提供可选的 AI 辅助分析，并明确事实、推断和不确定性。

### P4-M5 根因分析界面

- P4-F17 在 F12 中突出根因、影响节点和传播路径。
- P4-F18 展示判断依据、置信度、替代候选和建议操作。
- P4-F19 提供错误分组、趋势和已知问题管理。
- P4-F20 支持将分析结果复制或加入脱敏诊断包。

### 第四阶段测试与验收

- 单元测试：规则匹配、指纹稳定性、因果排序、置信度、聚类和建议选择。
- 数据集测试：使用人工标注的典型故障、连锁错误和相似错误样本评估准确率。
- 故障注入：认证失败、Gateway 崩溃、Codex 退出、网络超时、资源不足和配置错误。
- 安全测试：AI 分析输入脱敏、最小化、授权和不可用降级。
- 界面测试：根因突出、证据解释、候选切换、聚类和诊断包导出。
- 验收门槛：典型故障根因识别达到约定准确率；所有结论可解释；误判不得触发自动破坏性操作。

- P5-F02 建立 Debug Adapter Protocol 兼容层和能力协商。
- P5-F03 支持启动调试、附加进程、分离和安全终止。
- P5-F04 将调试会话与诊断 Trace、会话和源码地址关联。

### P5-M2 Node.js 与 Electron 调试适配器

- P5-F06 支持 Renderer 调试目标发现和附加。
- P5-F07 支持 Source Map 断点绑定与热更新后的重新绑定。
- P5-F08 处理进程重启、多进程切换和调试目标退出。

### P5-M3 Python 与 Runtime 调试适配器

- P5-F09 接入 Python DAP 调试 Runtime 和 Backend。
- P5-F10 支持本地、虚拟环境和远程 Python 进程附加。
- P5-F11 支持多线程、异步任务和子进程调试能力协商。
- P5-F12 处理 Runtime 重启、远程断线和调试器不可用降级。

### P5-M4 断点管理

- P5-F13 支持行断点、条件断点、命中次数断点和日志点。

### P5-M5 执行控制

- P5-F20 对取消、超时、断线和目标退出执行安全收尾。

### P5-M6 状态检查与求值

- P5-F21 查看参数、局部变量、闭包、全局变量和对象结构。
- P5-F22 支持受限表达式求值、监视表达式和复制值。
- P5-F23 对大型对象、循环引用、惰性属性和敏感值安全展开。
- P5-F24 默认禁止修改变量和执行具有副作用的表达式。

### P5-M7 调试工作台

- P5-F25 提供断点、调用栈、变量、监视和调试控制界面。
- P5-F26 将调试暂停位置与源码、诊断时间线和会话联动。
- P5-F27 明确显示当前调试目标、线程、权限和暂停原因。
- P5-F28 提供调试会话日志、恢复提示和紧急分离操作。

### 第五阶段测试与验收

- 协议测试：DAP 能力协商、事件顺序、会话生命周期和错误恢复。
- 适配器测试：Electron Main、Renderer、Node 子进程、Python、本地和 SSH Runtime。
- 功能测试：各种断点、暂停继续、单步、栈帧、变量、监视和异常暂停。
- 故障测试：目标退出、调试器崩溃、远程断线、进程重启、无效断点和 Source Map 变化。
- 安全测试：授权、敏感值遮蔽、表达式副作用限制、生产环境默认禁用和审计记录。
- 验收门槛：支持范围内的 Node/Python 目标可稳定完成完整调试流程；分离后业务可继续；调试失败不得破坏用户数据。

## 第六阶段：生产级诊断平台（Production Diagnostics）

状态：已完成（2026-07-18）。

目标：使诊断和调试能力能够安全、稳定、可治理地进入正式发布版本。  
依赖：前五阶段按产品范围选择启用。  
范围：6 个模块、24 个功能点。

### P6-M1 配置、权限与用户控制

- P6-F01 提供关闭、基础、详细和交互式调试等级。
- P6-F02 提供数据类型、保留时间、磁盘上限和远程传输设置。
- P6-F03 对源码、远程主机、调试附加和诊断包导出执行授权。
- P6-F04 提供企业策略、默认值、锁定项和审计记录。

- P6-F06 对诊断包执行内容清单、二次扫描和用户预览。

### 第六阶段测试与验收

- 灾难测试：进程强杀、系统重启、文件损坏、磁盘写满、权限变化和版本回滚。
- 安全测试：渗透检查、诊断包泄漏扫描、越权读取、表达式注入、传输和存储加密。
- 兼容测试：支持的 Windows 版本、安装/升级路径、旧诊断数据和不同 Runtime 版本。
- 发布测试：安装包冒烟、性能预算、功能开关、灰度、紧急关闭和支持流程演练。
- 验收门槛：所有发布门禁通过；安全评审无阻断项；长期运行满足资源预算；任何诊断故障均可降级且不影响核心业务。

## 阶段依赖与交付顺序

1. 第一阶段提供所有后续能力依赖的统一数据底座。
2. 第二阶段和第三阶段可并行开发，但两者完成后才能形成完整源码与深度链路闭环。
3. 第四阶段依赖前三阶段产生的稳定、可解释数据。
4. 第五阶段必须复用第二阶段的源码地址和第三阶段的进程链路，不建立独立的 Codex 专用调试体系。
5. 第六阶段贯穿前期设计，但在功能稳定后执行正式发布验收。

## 总体测试体系

### T1 单元与契约测试

覆盖协议、路径、映射、聚合、规则、调试会话、安全策略和数据格式；所有跨进程接口必须有版本化契约测试。

### T2 端到端集成测试

覆盖 Renderer、Preload、Electron Main、Gateway、Runtime、Backend、Codex、Workspace、SSH、终端、浏览器和工具链路。

### T3 故障与混沌测试

覆盖进程退出、网络中断、超时、乱序、重复、丢包、磁盘异常、权限变化、调试器退出、远程重启和数据损坏。

### T4 安全与隐私测试

覆盖敏感数据注入、路径越权、源码读取、诊断包、远程传输、表达式求值、企业策略和审计完整性。

### T5 性能与长稳测试

覆盖启动开销、事件吞吐、内存和磁盘上限、界面帧率、超大调用树、多日运行和降级策略。

### T6 界面与可用性测试

覆盖主题、缩放、键盘操作、错误恢复、无数据、超大数据、源码导航、根因解释和交互式调试流程。

### T7 发布与兼容测试

覆盖生产构建、Source Map、安装包、升级回滚、旧数据迁移、功能开关、灰度和紧急关闭。

## 验收管理规则

- 每个功能点必须关联实现、自动测试或明确的人工验收用例。
- 每个阶段必须独立通过专项测试，不能仅依赖全量回归结果。
- 阻断级和严重级缺陷清零后方可完成阶段验收。
- 涉及隐私、源码读取、远程连接和交互式调试的功能必须完成安全评审。
- 不受控地改变业务执行结果、泄露敏感数据或阻塞主流程，均为发布阻断项。
- 所有 Backend 和模块采用统一协议；Codex 只是首个适配对象，不允许形成专用分叉。
