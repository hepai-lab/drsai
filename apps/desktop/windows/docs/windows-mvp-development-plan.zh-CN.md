# OpenDrSai Windows App MVP 完整开发方案

## 1. 文档目的

本文定义 OpenDrSai Windows App 首个可公开验证版本的产品目标、功能边界、技术实现、开发阶段、测试方法、发布门槛和最终用户效果。

MVP 不是现有桌面能力的集合，也不以“功能数量最多”为目标。它只验证一个完整闭环：

> Windows 用户通过 OIDC 登录，打开本地项目，用自然语言让 DrSai 安全地理解、修改并验证项目，并能审阅全过程和最终差异。

本方案以 `apps/desktop/windows` 为唯一 Windows MVP 产品代码主线。`apps/desktop/legacy/drsai-desktop` 仅为历史归档，不承担新增产品开发。

## 2. 产品目标

### 2.1 目标用户

- 使用 Windows 10/11 x64 的开发者和科研工程师；
- 已拥有 HepAI/IHEP OIDC 身份；
- 希望 AI 直接处理本地项目，但需要明确的操作记录、审批与撤销边界；
- 不希望自行配置 API 地址、API Key、模型名称或本地 Gateway。

### 2.2 核心价值

用户安装应用后，无须理解模型供应商或智能体框架，只需登录、选择项目并描述任务。应用负责：

- 通过 OIDC 获得身份和服务授权；
- 自动启动并检查桌面运行时与 Gateway；
- 自动取得服务端允许使用的 Agent/模型策略；
- 为 Agent 提供受控的项目文件和命令执行能力；
- 在有风险的动作前请求用户批准；
- 展示执行进度、文件变化、测试结果和失败原因；
- 保存会话，以便下次继续。

### 2.3 MVP 成功标准

1. 干净 Windows 环境中，用户从启动应用到发出第一条有效请求不超过 3 分钟（不含组织 OIDC 页面中的人工认证时间）。
2. 用户不需要填写 API Key、服务 URL 或模型名。
3. 用户能完成“打开项目 → 提问 → Agent 读取项目 → 修改文件 → 执行验证 → 审阅 Diff → 接受或拒绝”的完整流程。
4. 应用异常关闭后，项目、会话和已完成操作记录仍可恢复。
5. 未经批准，应用不能执行超出当前可信工作区的写入、危险命令或敏感外部访问。
6. 20 次连续核心场景回归中，无主进程崩溃、会话丢失或未授权写入。

## 3. 产品边界

### 3.1 MVP 包含

- OIDC 唯一正式登录入口；
- 安全会话保存、刷新、失效处理与退出；
- 本地项目选择和工作区信任；
- 单项目、多会话；
- 流式聊天；
- 项目文件读取、搜索、创建和编辑；
- 工作区内受控命令执行；
- Git 状态及文件 Diff；
- 风险审批、任务停止和失败恢复；
- 本地会话及执行记录持久化；
- Windows 安装、卸载、自动更新和诊断日志；
- 简体中文主界面，必要处保留英文技术名词。

### 3.2 MVP 不包含

- 用户自行配置 API Key、Base URL 或默认模型；
- 密码登录、微信登录和公开版开发者旁路；
- 多 Agent 编排器、Agent 广场和可视化流程编辑器；
- Skills/插件市场、Memory 管理、定时任务、IM 渠道；
- SSH 远程工作区、语音、Office 深度集成和浏览器自动化；
- 多工作树协作、复杂分支合并和团队权限管理；
- macOS、Linux 和 ARM64 发布。

上述代码可以暂时保留，但正式构建中不得出现在主导航或首次使用路径中。

## 4. 核心用户流程

### 4.1 首次启动

1. 应用显示品牌页并并行完成本地组件自检。
2. 显示一个主按钮：“使用 HepAI 登录”。
3. 点击后打开系统默认浏览器，执行 OIDC Authorization Code Flow with PKCE。
4. 浏览器认证成功后回到桌面应用；应用验证签名、issuer、audience、expiry、state 和 nonce。
5. 应用取得用户基本信息、角色/组和访问令牌，但不向 renderer 暴露原始令牌。
6. 应用自动启动 Gateway，并用 OIDC access token 获取服务端能力和默认 Agent/模型策略。
7. 用户选择本地项目目录并确认工作区信任。
8. 进入空白会话，输入框获得焦点。

首次启动不出现模型配置页。服务端无可用能力时显示“当前账号没有可用的 DrSai 服务”，并提供重试、重新登录和复制诊断信息。

### 4.2 日常启动

1. 读取主进程加密保存的 OIDC 会话。
2. 若 access token 即将过期，使用 refresh token 静默刷新。
3. 恢复最近项目和会话。
4. 自动检查 Gateway；正常时直接进入工作区。
5. 刷新失败或服务端返回 401 时，清理失效会话并回到登录页，不循环重试。

### 4.3 完成任务

1. 用户描述任务，可引用工作区文件。
2. Agent 显示当前阶段：分析、读取、修改、验证或等待审批。
3. 只读操作自动执行并记录。
4. 文件修改先进入变更集；界面展示 Diff。
5. 低风险验证命令可以按策略执行；高风险操作进入审批中心。
6. 用户可以随时停止任务。
7. 完成时显示摘要：做了什么、改了哪些文件、运行了哪些验证、是否通过、还有什么风险。
8. 用户接受变更、拒绝变更或继续对话修订。

## 5. 功能设计

### 5.1 OIDC 身份与服务引导

正式构建只提供 OIDC 登录。采用当前已有的系统浏览器 + `127.0.0.1` 临时端口回调方案：

- Authorization Code + PKCE S256；
- 每次登录生成新的 state、nonce、verifier；
- 从 discovery document 获取 authorization、token、JWKS 和 revocation endpoint；
- 只接受预期 issuer、client ID audience 和 `hai-api` audience；
- 只接受 RS256 且必须通过 JWKS 验签；
- token 只保存在 Electron main process；
- refresh/access/id token 使用 Electron `safeStorage` 加密；
- renderer 只接收脱敏后的用户与会话状态；
- “保持登录”才申请 `offline_access`；
- 退出时尽力撤销 refresh token，并始终清理本地会话。

登录成功后的服务发现由后端返回，不把模型配置责任转移给桌面端。建议定义统一 bootstrap 响应：

```json
{
  "user": { "id": "...", "name": "...", "roles": [], "groups": [] },
  "capabilities": { "chat": true, "agent": true, "tools": ["files", "shell", "git"] },
  "defaults": { "agent_id": "drsai", "model_alias": "default" },
  "limits": { "max_context_bytes": 1048576, "max_concurrent_runs": 1 }
}
```

桌面端可以显示服务端返回的模型/Agent 名称，但 MVP 不允许用户编辑 endpoint、Key 或底层模型参数。

### 5.2 本地运行时与 Gateway

- App 启动后由主进程管理 Gateway 生命周期；
- 使用随机或受控本地端口，只监听 loopback；
- `/health` 检查进程存活，`/v1/models` 或 bootstrap API 检查实际可用性；
- 所有聊天和 Agent 请求携带 `Authorization: Bearer <OIDC access token>`；
- 传递认证模式和用户标识，但日志中必须脱敏；
- 启动超时、端口冲突、版本不匹配分别给出可操作提示；
- UI 不要求用户点击“启动 Gateway”，只在失败时提供“重试”和“修复运行时”。

### 5.3 工作区

- 使用系统目录选择器打开项目；
- 保存最近项目列表，项目不存在时标为不可用；
- 第一次打开目录时显示信任确认，说明 Agent 可以读取文件并在批准后修改和运行命令；
- 主进程对所有路径做绝对路径解析和工作区边界校验；
- 默认忽略 `.git`、依赖缓存、构建产物、大文件和常见密钥文件；
- 可切换项目，但同一窗口同时只有一个活动项目；
- 会话必须绑定工作区，禁止把 A 项目的文件上下文错误发送到 B 项目会话。

### 5.4 对话与任务运行

- 支持文本输入、换行、发送、停止和重新生成；
- 流式显示回答；
- 工具调用以折叠卡片展示：工具名、目标、状态、耗时与简要结果；
- 同一会话 MVP 只允许一个运行中任务；
- 支持取消信号，并在 UI 中区分“已请求停止”和“已停止”；
- 网络中断时保留已收到内容，允许重试但不重复应用已完成的写操作；
- 每个运行具有唯一 request/run ID，便于关联日志、工具调用和变更集。

### 5.5 文件上下文与修改

- Agent 可列出、搜索和读取工作区内文件；
- 文件读取有大小、数量和总上下文预算；
- 二进制文件默认只提供元数据；
- 修改采用临时变更集或可恢复写入流程；
- 写入前检查文件是否自读取后被外部程序修改；
- 冲突时停止覆盖并要求用户重新载入；
- Diff 支持逐文件查看、接受全部和拒绝全部；逐块接受不作为 MVP 硬要求；
- 拒绝后恢复至任务开始前内容，并保留审计记录。

### 5.6 命令执行与审批

命令在工作区目录中执行，继承最小必要环境。策略分三档：

| 类型 | 示例 | MVP 行为 |
|---|---|---|
| 只读/低风险 | `git status`、读取版本、列目录 | 自动执行并记录 |
| 工作区内可变更 | 测试、构建、格式化、安装项目依赖 | 执行前显示命令、目录和风险，用户批准 |
| 高风险/越界 | 删除目录、系统配置、工作区外写入、强制 Git、提权 | 默认阻止；确需支持时逐次明确批准 |

审批必须绑定精确的命令、工作目录和 run ID，不能用一次批准授权后续不同命令。终端输出应限制内存占用，并对 API Key、Bearer token、cookie 等内容脱敏。

### 5.7 Git 与结果审阅

- 显示工作区是否为 Git 仓库；
- 显示任务开始前和当前工作区状态；
- 区分用户原有修改与 Agent 新修改；
- 不自动提交、不自动 push；
- 完成卡片列出修改文件、增删行、验证命令和退出码；
- 非 Git 项目仍支持文件 Diff 和回滚。

### 5.8 会话与本地持久化

- 会话支持新建、重命名、删除和恢复；
- 保存用户消息、Agent 消息、工具摘要、审批决定、变更摘要和 run 状态；
- 不保存原始 access/refresh token 到会话数据库；
- 应用崩溃后将未完成 run 标记为“意外中断”，不自动重放工具操作；
- 删除项目不会删除用户项目文件；
- 提供“清除本地数据”和“复制诊断信息”。

### 5.9 界面信息架构

正式 MVP 主导航只保留“工作区”和“设置/诊断”。工作区采用三栏：

```text
┌──────────────┬────────────────────────────┬──────────────────────┐
│ 项目 / 会话  │ 对话与执行时间线           │ 文件 / Diff          │
│              │                            │                      │
│ 当前项目     │ 用户问题                   │ 变更文件列表         │
│ + 新建会话   │ Agent 回答                 │ 文件内容或差异       │
│ 最近会话     │ 工具、审批、验证状态       │ 接受 / 拒绝变更      │
└──────────────┴────────────────────────────┴──────────────────────┘
```

窄窗口允许右栏变为抽屉。底部状态只显示身份、Gateway、当前工作区信任和版本，不暴露实现噪声。

### 5.10 设置与诊断

设置页只包含：

- 当前登录用户、重新登录和退出；
- 语言与主题；
- 应用版本和更新状态；
- 本地运行时/Gateway 状态；
- 日志目录、复制诊断和运行修复；
- 清除会话或全部本地数据。

正式版不展示 API Key、模型 endpoint、开发者旁路和 OIDC 调试事件。调试面板仅在开发构建或显式诊断开关下可用。

## 6. 非功能要求

### 6.1 安全

- renderer 启用 context isolation，禁用 Node integration；
- 所有本地能力通过类型化 preload IPC 暴露；
- IPC handler 验证参数类型、长度、路径和调用上下文；
- OIDC token 不进入 renderer、URL 日志、崩溃报告或聊天记录；
- 外部 URL 只允许 HTTPS 和配置的 OIDC 主机；
- Loopback callback 绑定 `127.0.0.1`，校验 state，并在一次成功或超时后关闭；
- 工作区路径使用解析后的真实路径做边界判断，防止 `..` 和链接逃逸；
- 打包产物签名，更新包校验签名和 SHA256。

### 6.2 可靠性与性能

- 冷启动到可交互登录页：目标小于 3 秒；
- 已登录且 Gateway 健康时进入工作区：目标小于 5 秒；
- 首个流式 token 的桌面额外延迟：目标小于 300 ms；
- 10 万文件项目扫描不能阻塞 renderer；
- 单次终端输出、文件预览和日志都有上限；
- 主进程、Gateway 或 renderer 任一故障均给出可恢复状态，不出现无限 loading。

### 6.3 可观测性

- 日志包含 timestamp、level、component、run ID 和脱敏错误；
- 记录启动阶段、OIDC 阶段、Gateway 健康、请求状态、工具状态和退出原因；
- 默认不记录提示词全文、文件正文和 token；
- 诊断包包含版本、OS、组件状态和脱敏日志，不包含项目源码。

## 7. 技术实现分层

### 7.1 Electron main process

负责 OIDC、token 加密、窗口生命周期、Gateway/子进程、文件系统、命令、Git、持久化、更新和日志。任何敏感或可变更系统状态的能力都不能下放 renderer。

### 7.2 Preload

只暴露最小类型化接口，例如：

- `auth.getSession/startOidcLogin/cancel/logout`；
- `workspace.choose/open/getRecent/trust`；
- `chat.start/cancel/subscribe`；
- `changes.list/accept/reject`；
- `approvals.list/decide`；
- `diagnostics.get/copy/openLogs`。

### 7.3 Renderer

只负责状态展示和用户意图收集。不得直接读取磁盘、启动命令、持有 token 或直接调用远端模型接口。

### 7.4 Gateway/backend

负责验证 OIDC bearer token、解析账号能力、选择服务端模型/Agent、执行 Agent 循环和返回标准流事件。桌面与 Gateway 应约定版本化事件协议，至少包含 message delta、tool start/end、approval request、file change、run completed/failed。

## 8. 开发阶段与交付物

### 阶段 0：范围收敛与基线

- 指定 `apps/desktop/windows` 为唯一 MVP 主线；
- 建立功能开关，隐藏所有非 MVP 导航；
- 固定桌面—Gateway 协议和 OIDC bootstrap contract；
- 建立 MVP 验收矩阵和已知问题清单。

完成标准：开发构建只有 MVP 信息架构，协议有类型定义和契约测试。

### 阶段 1：零配置 OIDC 首次启动

- 登录页仅保留 HepAI OIDC；
- 完成登录、取消、超时、刷新、退出和失效回退；
- 登录后自动 bootstrap 能力和启动 Gateway；
- 移除首次启动模型/API Key 配置；
- 将开发者旁路限制在未打包开发环境。

完成标准：干净用户目录可通过真实或测试 OIDC 登录并发出带 bearer token 的 Gateway 请求。

### 阶段 2：项目与会话闭环

- 项目选择、信任、最近项目；
- 单项目多会话和本地持久化；
- 流式聊天、取消、错误重试；
- 会话和项目隔离。

完成标准：重启应用后能恢复项目与会话，错误项目上下文不会串用。

### 阶段 3：安全执行与变更审阅

- 文件读取/搜索/写入边界；
- 命令执行策略和审批中心；
- Git/文件 Diff、接受和拒绝；
- 外部修改冲突检测；
- 完成摘要和验证结果。

完成标准：真实示例项目可以完成完整修改闭环，拒绝变更后文件恢复正确。

### 阶段 4：安装、恢复与发布质量

- 将运行时随安装流程自动准备；
- 自动更新、版本匹配和修复；
- 崩溃恢复、日志脱敏和诊断包；
- 签名安装包与干净 Windows 验证；
- 性能、可访问性和窄窗口处理。

完成标准：满足本文所有 P0 验收用例并产出签名候选安装包。

## 9. 测试与验证方法

### 9.1 单元测试

| 模块 | 必测内容 |
|---|---|
| OIDC | PKCE、state/nonce、claim 校验、过期判断、refresh 合并、退出清理 |
| 路径安全 | `..`、大小写、UNC、junction/symlink、工作区边界、保留设备名 |
| 命令策略 | 风险分类、精确审批绑定、目录限制、环境变量脱敏 |
| Diff/变更集 | 新建、修改、删除、二进制、编码、换行、外部冲突、拒绝恢复 |
| 持久化 | 原子写入、损坏恢复、版本迁移、崩溃中 run 状态修正 |
| SSE/事件 | 分片、乱序保护、断流、重复完成事件、取消竞态 |

要求：核心安全与状态模块语句/分支覆盖率不低于 80%，路径安全和 OIDC 校验采用表驱动边界用例。

### 9.2 契约与集成测试

- Fake OIDC issuer 提供 discovery、JWKS、authorize、token、refresh 和 revoke；
- Fake Gateway 验证 bearer token、auth mode、user header 和事件协议；
- 覆盖错误 issuer、错误 audience、错误 nonce、过期 token、JWKS 轮换、401 刷新和撤销失败；
- IPC 测试验证 renderer 无法得到 token，非法参数会被 main process 拒绝；
- 工作区测试使用临时目录和真实 Git 仓库，验证原有修改不会被回滚；
- Gateway 进程测试覆盖端口冲突、启动超时、异常退出和版本不匹配。

现有 `verify:oidc-login`、`verify:e2e-oidc-login` 和 `verify:e2e-oidc-hai` 作为基础，新增 bootstrap、工作区隔离和变更回滚契约验证。

### 9.3 Renderer/UI 测试

- 登录页正式模式没有 API Key、密码和模型字段；
- 登录等待、取消、超时、失败和成功状态可见；
- 空项目、无会话、运行中、等待审批、断网、Gateway 故障均有明确界面；
- 工具和 Diff 可用键盘访问，焦点顺序正确；
- 1280×720、1440×900、1920×1080 和 200% 缩放下无关键控件遮挡；
- 中文长错误信息不会破坏布局；
- 视觉快照覆盖首次启动、主工作区、审批、Diff 和完成摘要。

### 9.4 Electron E2E 核心场景

P0 场景全部在真实 main/preload/renderer 路径执行：

1. 首次启动 → OIDC → 选择项目 → 首条聊天成功；
2. 保持登录 → 重启 → 静默刷新 → 恢复会话；
3. token 失效 → 返回登录页 → 重新登录；
4. Agent 读取文件 → 修改 → 运行测试 → 显示 Diff → 接受；
5. Agent 修改 → 用户拒绝 → 文件完整恢复；
6. 用户原有未提交修改存在时执行任务，不覆盖或误回滚；
7. 危险命令等待审批，拒绝后不启动进程；
8. 运行中取消，无后续写入或命令残留；
9. 模拟 Gateway 崩溃，UI 给出重试且会话不丢失；
10. 模拟应用强制退出，重启后 run 标为意外中断；
11. 切换项目后，上个项目内容不出现在新请求中；
12. 退出登录后 token 文件被清理，旧 bearer token 不再使用。

### 9.5 安全验证

- 静态扫描确认 renderer bundle 不包含 token、client secret 或开发者凭据；
- 尝试通过 IPC 读取工作区外文件、写入工作区外路径和执行越界命令；
- 验证日志、错误信息、诊断包和崩溃信息中的 token/密钥脱敏；
- 验证恶意项目中的链接、超大文件、ANSI 控制字符和提示注入文本不会绕过策略；
- 验证安装包和更新包签名、哈希、允许下载域和降级保护。

### 9.6 性能与稳定性验证

- 1 千、10 万文件项目启动与搜索基准；
- 10 MB 文本、超长单行、二进制和大量终端输出的内存基准；
- 8 小时运行和 100 次连续对话 soak test；
- Gateway 连续重启、网络抖动和 refresh 并发压力测试；
- 20 次核心闭环无崩溃回归作为候选发布硬门槛。

### 9.7 干净机器验收

至少覆盖 Windows 10 22H2 和 Windows 11 当前受支持版本：

- 无 Node、Python、Git 的普通用户环境；
- 非管理员安装或明确提示需要的权限；
- 中文用户名、空格路径和非 ASCII 项目路径；
- 企业代理、离线、DNS 失败和防火墙拦截；
- 安装、升级、修复、卸载以及保留/清除用户数据。

## 11. 最终实现效果

用户最终看到的不是一个需要搭建的 Agent 平台，而是一款可直接工作的 Windows 应用：

1. 双击安装并启动 OpenDrSai。
2. 点击“使用 HepAI 登录”，在系统浏览器完成组织认证。
3. 回到应用后直接选择项目，不配置模型或 API Key。
4. 输入“分析这个项目并修复测试失败”。
5. 界面实时显示 DrSai 正在读取哪些内容、运行什么验证，以及哪些动作需要批准。
6. 修改完成后在右侧看到清晰 Diff 和测试结果。
7. 用户接受或拒绝变更；应用给出简洁结果摘要。
8. 下次启动自动恢复身份、项目和会话；身份失效时明确要求重新登录。

最终 MVP 应给用户四个清晰感受：

- **零配置**：身份认证同时完成服务授权和默认能力选择；
- **可理解**：始终知道 Agent 当前在做什么；
- **可控制**：敏感动作需要批准，修改可以审阅和拒绝；
- **可恢复**：失败、断网、崩溃和重启不会悄悄丢失状态或重复执行操作。

## 12. MVP 完成定义

只有同时满足以下条件，才能宣布 MVP 完成：

- 所有 P0 功能已实现且正式构建中不存在模型/API Key 配置路径；

- 真实项目的读取、修改、验证、Diff 和接受/拒绝闭环通过；
- 安全边界测试未发现未授权文件、命令或 token 泄漏；
- 干净 Windows 机器安装和升级验证通过；
- 20 次连续核心回归无崩溃和数据丢失；
- 已知问题、支持范围、日志收集和回滚方式均有发布文档。
